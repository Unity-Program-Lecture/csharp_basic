# 🚀 유니티 좌표계 마스터: 월드(World) vs 로컬(Local)

유니티에서 물체의 위치를 다룰 때 "여기가 어디인가?"에 대한 대답은 두 가지 방식으로 나뉩니다. 이 개념을 모르면 캐릭터가 엉뚱한 방향으로 가거나 UI가 화면 밖으로 나가는 현상을 겪게 됩니다.

---

## 1. 월드 좌표 (World Space): "지구의 위도와 경도"

월드 좌표는 유니티 게임 세상 전체의 **'절대적인 기준'**입니다.

- **원점 (0, 0, 0)**: 우주의 중심입니다. 모든 물체는 이 중심으로부터 얼마나 떨어져 있는지를 계산할 수 있습니다.
- **방향**: 우주 전체의 동서남북이 정해져 있습니다. (예: 어떤 물체든 +Y 방향은 무조건 '하늘'입니다.)
- **C# 코드**: `transform.position`을 사용하면 월드 좌표를 가져옵니다.

---

## 2. 로컬 좌표 (Local Space): "내 방 안에서의 위치"

로컬 좌표는 **'부모(Parent) 물체를 기준'**으로 하는 상대적인 위치입니다.

- **기준점**: 나를 품고 있는 부모 물체의 중심이 곧 (0, 0, 0)이 됩니다.
- **방향**: 부모가 회전하면 나의 '앞(Z)' 방향도 함께 바뀝니다.
- **비유**: 지구가 자전(회전)해도 내 방 책상의 위치는 내 방 안에서 항상 똑같은 곳에 있는 것과 같습니다.
- **C# 코드**: `transform.localPosition`을 사용합니다.

---

## 3. 왜 두 가지를 구분해야 하나요? (중요!)

### ① 부모-자식 관계 (Hierarchy)
- 캐릭터(부모)가 손에 검(자식)을 들고 있다면, 캐릭터가 전 세계 어디를 돌아다녀도 검의 **로컬 좌표**는 항상 (0, 0, 1) 정도로 고정되어 있습니다. 그래야 캐릭터가 움직일 때 검이 손에서 떨어지지 않습니다.

### ② 회전과 이동 알고리즘
- "앞으로 가라!"라는 명령을 내릴 때:
    - **월드 기준**: 세상의 북쪽으로 이동합니다.
    - **로컬 기준**: 캐릭터가 바라보고 있는 코 방향(Z축)으로 이동합니다. (게임 개발에서는 대부분 이 방식을 씁니다.)

---

## 4. 한 눈에 비교하기

| 구분 | 월드 좌표 (World) | 로컬 좌표 (Local) |
| :--- | :--- | :--- |
| **기준** | 게임 세상의 절대 중심 | 부모 오브젝트의 중심 |
| **코드** | `transform.position` | `transform.localPosition` |
| **부모 이동 시** | 값이 변함 | **값이 변하지 않음** |
| **주요 용도** | 길찾기(A*), 전체 맵 배치 | 캐릭터 장착 아이템, UI 요소 |

---

## 💡 팁: 인스펙터(Inspector)의 진실
유니티 에디터의 인스펙터 창에 표시되는 위치(Position) 값은 사실 **로컬 좌표(localPosition)**입니다. 
- 만약 부모가 없는 물체라면 부모가 곧 '월드'이므로 월드 좌표와 똑같게 보이지만, 
- 누군가의 자식으로 들어가는 순간 그 값은 부모로부터의 거리로 바뀝니다.

1. 부모 오브젝트를 (10, 0, 0)으로 옮겼을 때, 자식 오브젝트의 `localPosition`이 (0, 0, 0)이라면 이 자식의 실제 `position`은 어디일까요?
2. 캐릭터의 코 방향으로 총알을 발사하고 싶을 때, 어떤 좌표계를 기준으로 힘을 주어야 할까요?
3. 전 세계에 단 하나뿐인 보물 상자의 위치를 기록하고 싶을 때는 어떤 좌표를 저장하는 것이 안전할까요?
