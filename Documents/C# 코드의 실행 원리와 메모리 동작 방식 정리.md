# C\# 코드의 실행 원리와 메모리 동작 방식 정리

C\# 코드가 컴퓨터 하드웨어에서 어떤 과정을 거쳐 실행되는지, 그리고 메모리가 어떻게 관리되는지 입문자가 이해하기 쉽게 정리한 문서입니다.

---

## 0\. 컴퓨터의 기본 구조 (무대 설명)

C\# 프로그램이 실행되는 하드웨어의 핵심 삼총사입니다.

* **CPU (요리사):** 실제로 데이터를 계산하고 명령을 실행합니다. 0과 1로 된 '기계어'만 이해할 수 있습니다.  
* **메모리 (조리대):** 실행 중인 프로그램의 코드와 데이터를 임시로 올려두는 공간입니다. 속도가 매우 빠릅니다.  
* **보조기억장치 (창고):** 프로그램(`.exe`)이 영구적으로 저장된 곳입니다.

---

## 1\. C\# 실행 과정 (번역 단계)

사람이 쓴 코드가 CPU가 이해하는 언어로 바뀌는 과정입니다.

1. **C\# 코드 작성:** `.cs` 파일에 사람이 읽기 편한 코드를 작성합니다.  
2. **1차 컴파일 (표준화):** 컴파일러가 코드를 \*\*CIL(공통 중간 언어)\*\*로 바꿉니다. 어떤 운영체제에서도 돌아갈 수 있는 표준 레시피가 됩니다.  
3. **2차 컴파일 (현지화):** 프로그램 실행 시 **JIT(Just-In-Time) 컴파일러**가 해당 CPU에 최적화된 \*\*기계어(0, 1)\*\*로 실시간 번역합니다.  
4. **하드웨어 실행:** 번역된 기계어가 CPU에 전달되어 실제로 동작합니다.

---

## 2\. 메모리 운영 체계 (스택 vs 힙)

프로그램이 실행될 때 메모리(RAM)는 효율적인 관리를 위해 구역을 나눕니다.

### 🏢 스택 (Stack \- 전용 서랍)

* **특징:** 메소드가 실행될 때마다 전용 서랍(스택 프레임)이 생기고, 종료되면 즉시 서랍을 통째로 비웁니다.  
* **저장 내용:** 기본 숫자 타입(int, bool 등), 객체의 주소값(보관증).  
* **장점:** 관리가 매우 빠르고 자동적입니다.

### 🏗️ 힙 (Heap \- 대형 창고)

* **특징:** `new` 키워드로 만든 클래스(객체)들이 사는 넓은 공용 공간입니다.  
* **저장 내용:** 실제 객체의 덩어리 데이터.  
* **관리:** 가비지 컬렉터(GC)라는 청소부가 더 이상 쓰지 않는 물건을 나중에 치워줍니다.

---

## 3\. 메소드 내부의 동작 원리

### 💡 변수 선언과 접근 (오프셋 개념)

* **동시 확보:** 메소드가 시작될 때 필요한 변수 공간(서랍 칸)은 한꺼번에 예약됩니다.  
* **직접 접근:** 세 번째 변수를 먼저 사용하더라도 CPU는 "시작점에서 두 칸 옆"이라는 \*\*오프셋(주소 계산)\*\*을 통해 즉시 점프하여 접근합니다. 순서대로 거쳐갈 필요가 없습니다.

### 💡 참조(Reference)의 전달

* 객체를 변수에 할당할 때, 서랍(Stack)에는 진짜 물건이 아닌 \*\*'창고 주소(보관증)'\*\*만 저장됩니다.  
* 다른 메소드에 객체를 넘길 때도 이 \*\*'보관증'\*\*만 복사해주기 때문에, 여러 곳에서 동시에 똑같은 창고 물건을 다룰 수 있게 됩니다.

---

## 4\. 요약 (한 줄 정리)

**"C\# 코드는 중간 언어로 번역되어 보관되다가, 실행 순간 CPU를 위한 기계어로 통역되어 메모리(조리대)에 올라가고, CPU 요리사는 스택(서랍)과 힙(창고)을 오가며 레시피를 수행합니다."**
