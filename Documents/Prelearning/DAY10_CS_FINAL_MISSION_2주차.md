## ⚔️ 2주차 최종 미션: "RPG 인벤토리 완성하기"

### **[미션 조건]**

1. **아이페이스와 클래스 설계**
   - `IUseable` 인터페이스를 만듭니다. (`Use()` 메소드 포함)
   - `Item` 추상 클래스(또는 부모 클래스)를 만듭니다. (이름, 개수 변수 포함)
   - `Potion`, `Weapon` 클래스를 만들어 `Item`을 상속받고 `IUseable`을 구현합니다.
     - `Potion.Use()`: "포션을 마십니다. 체력이 회복됩니다." 출력
     - `Weapon.Use()`: "무기를 장착합니다. 공격력이 올라갑니다." 출력

2. **인벤토리 시스템 구현**
   - `List<Item>`을 사용하여 아이템들을 보관하는 `Inventory` 클래스를 만듭니다.
   - `AddItem(Item item)`: 아이템을 리스트에 추가합니다.
   - `ShowAllItems()`: 현재 인벤토리에 있는 모든 아이템의 이름을 출력합니다.
   - `UseItem(string name)`: 입력받은 이름의 아이템이 리스트에 있다면 `Use()`를 실행하고, 소모품(포션)이면 리스트에서 삭제합니다.

3. **메인 함수 로직**
   - 인벤토리에 포션 2개와 무기 1개를 넣습니다.
   - 사용자에게 이름을 입력받아 해당 아이템을 사용하게 합니다.
   - 인벤토리 목록이 실시간으로 변하는지 확인하세요.

---

### **[정답 예시 가이드 - 힌트]**
**미션:** List와 foreach를 활용해 특정 이름을 가진 아이템을 검색하고 사용하는 로직을 구현합니다.

    if (item.name == searchName)
    {
        item.Use(); // 인터페이스 약속대로 사용하기!

    }
}

## 4. 10일차 심화 미션: "미니 던전 크롤러"

**[미션 목표]**
1주차와 2주차에 걸쳐 배운 C#의 핵심 문법과 객체지향 원칙을 모두 활용하여, 하나의 완성된 게임 시스템을 설계합니다. 각 모듈이 어떻게 유기적으로 상호작용하는지 이해하고 전체적인 프로그램 아키텍처를 구상하는 능력을 기릅니다.

---

### 1) 요구 사항

#### 1. 시스템 아키텍처 통합
* **상속 및 다형성**: 다양한 몬스터 객체들을 담는 `List<Monster>`를 관리합니다.
* **인터페이스**: 공격 가능한 모든 대상(`IDamageable`)과 아이템(`IUsable`)의 규격을 유지합니다.
* **제네릭**: 몬스터와 아이템을 모두 보관할 수 있는 범용 창고(`Storage<T>`) 클래스를 활용합니다.
* **자료구조**: 턴 순서는 `Queue`로, 최근 전투 기록은 `Stack`으로 관리합니다.

#### 2. 핵심 게임 루프 설계
* **준비**: 플레이어 정보 설정 및 몬스터 무리(`Horde`) 생성. 모든 캐릭터를 `Queue`에 등록합니다.
* **전투**: 큐에서 다음 순서를 꺼내 공격/회복/로그 확인 중 하나의 행동을 수행합니다.
* **보상**: 몬스터 처치 시 `Dictionary` 인벤토리에 아이템 개수를 추가합니다.
* **결과**: 필드에 남은 몬스터가 없으면 "던전 클리어", 플레이어 체력이 0이면 "게임 오버"를 출력합니다.

---

### 2) 프로그래밍 힌트
* 한 번에 모든 것을 만들려 하지 말고, 3일차부터 진행해온 각 단계별 기능을 하나씩 복사해와서 연결해 보세요.
* `while` 루프를 사용하여 게임이 끝날 때까지 반복되는 구조를 만듭니다.
* 각 기능을 별도의 클래스(예: `DungeonManager`, `CombatLogger`)로 분리하여 코드의 가독성을 높여 보세요.
