# 🚀 8일차: 만능 기계 제작법 (제네릭 - Generics)

오늘의 목표는 **"데이터 타입을 미리 정해두지 않고, 사용할 때마다 자유롭게 정해서 쓰는 '만능 코드'를 만드는 법을 배운다"**입니다.

---

## 1. 제네릭(Generics): "무엇이든 찍어내는 만능 틀"
붕어빵 틀에 팥을 넣으면 팥 붕어빵, 슈크림을 넣으면 슈크림 붕어빵이 나오듯, **'재료(타입)'**만 바꾸면 똑같은 기능을 수행하는 만능 코드를 만드는 기술입니다.

### 💡 이 단어는 무슨 뜻인가요?
- **`<T>` (Type)**: "아직 타입을 정하지 않았다!"는 뜻의 임시 이름표입니다. (보통 Type의 약자인 T를 씁니다.)
- **일반화**: "특정 사람(int, string 등) 전용이 아닌, **모든 사람 공용**"으로 만드는 과정을 말합니다.

### 💻 실습 예제: 어떤 물건이든 교환해주는 만능 교환기
**미션:** 제네릭 메소드 <T>를 정의하여 데이터 타입에 관계없이 두 변수의 값을 서로 교환(Swap)하는 기능을 구현해 보세요.

<details>
<summary>코드 보기</summary>

```csharp
using System;

namespace Day08
{
    internal class Program
    {
        // 1. 제네릭 메소드 만들기 (T 자리에 어떤 타입이든 올 수 있습니다!)
        static void Swap<T>(ref T a, ref T b)
        {
            T temp = a;
            a = b;
            b = temp;
        }

        static void Main(string[] args)
        {
            // 정수 교환
            int n1 = 10, n2 = 20;
            Swap<int>(ref n1, ref n2); 
            Console.WriteLine("n1: {0}, n2: {1}", n1, n2);

            // 문자열 교환
            string s1 = "사과", s2 = "포도";
            Swap<string>(ref s1, ref s2);
            Console.WriteLine("s1: {0}, s2: {1}", s1, s2);
        }
    }
}
```

</details>

## 2. 제네릭 클래스: "무엇이든 담는 만능 상자"
데이터를 보관할 때, 타입을 정해두지 않고 **나중에 결정**할 수 있습니다. `List<T>`가 바로 이 원리로 만들어진 클래스입니다.

### 💻 실습 예제: 나만의 보관함 클래스
**미션:** 제네릭 클래스를 설계하여 다양한 타입의 데이터를 안전하게 보관하고 꺼낼 수 있는 만능 상자를 만들어 보세요.

<details>
<summary>코드 보기</summary>

```csharp
using System;

namespace Day08
{
    // 1. <T> 타입의 아이템을 하나 보관하는 클래스
    class Box<T>
    {
        private T item;

        public void Store(T item)
        {
            this.item = item;
            Console.WriteLine("{0}을(를) 상자에 보관했습니다.", item);
        }

        public T Retrieve()
        {
            return item;
        }
    }

    internal class Program
    {
        static void Main(string[] args)
        {
            // 정수 보관함
            Box<int> intBox = new Box<int>();
            intBox.Store(100);

            // 문자열 보관함
            Box<string> stringBox = new Box<string>();
            stringBox.Store("소중한 편지");
        }
    }
}
```

</details>

## 3. 왜 제네릭을 쓰나요?
1. **중복 제거**: `int`용 메소드, `string`용 메소드를 따로 만들 필요 없이 **하나의 코드**로 해결됩니다.
2. **성능**: 예전 방식(`object`)보다 훨씬 빠르고 **메모리 낭비**가 적습니다.
3. **안전성**: 엉뚱한 타입의 데이터가 들어오는 것을 미리 막아줍니다.

## 4. 8일차 미션: "만능 출력기 만들기"
다음 조건에 맞는 프로그램을 만들어보세요.

1. `Logger` 클래스를 만듭니다.
2. `PrintInfo<T>(T data)`라는 제네릭 메소드를 만듭니다.
   - 이 메소드는 받은 데이터를 "--- 로그: [데이터] ---" 형식으로 출력합니다.
3. `Main`에서 `int`, `double`, `string` 타입을 각각 출력기에 넣어서 확인해보세요.
   - 예: `PrintInfo(123);` -> "--- 로그: 123 ---"
   - 예: `PrintInfo("Hello");` -> "--- 로그: Hello ---"

**Tip**: `<T>`는 꼭 T가 아니어도 되지만(`U`, `V`, `Data` 등), 관례상 **T**를 가장 많이 씁니다!

## 5. 8일차 심화 미션: "범용 보관함 시스템"

**[미션 목표]**
데이터 타입에 구애받지 않고 다양한 객체를 처리할 수 있는 제네릭(Generic) 클래스와 메서드를 설계합니다. 이를 통해 코드의 재사용성을 극대화하고 타입 안정성을 유지하는 방법을 학습합니다.

---

### 1) 요구 사항

#### 1. 제네릭 보관함 설계 (`Generic Class`)
* `Box<T>` 클래스를 만듭니다. 여기서 `T`는 담길 물건의 타입입니다.
* **`Store(T item)`**: 물건을 박스에 담습니다.
* **`T GetItem()`**: 박스에서 물건을 꺼내 반환합니다.

#### 2. 다양한 타입 활용
* **`Box<Monster>`**: 몬스터를 포획해서 보관하는 '몬스터 볼' 역할을 수행합니다.
* **`Box<IUsable>`**: 6일차에서 만든 인터페이스를 활용하여, 사용 가능한 아이템들을 보관하는 '아이템 가방' 역할을 수행합니다.

#### 3. 제네릭 메서드 구현
* 두 객체의 정보를 바꾸는 `Swap<T>(ref T a, ref T b)` 메서드를 제네릭으로 구현합니다.
* 이를 이용해 두 명의 플레이어가 가진 아이템을 서로 교환하거나, 두 마리 몬스터의 위치를 바꾸는 로직을 시뮬레이션해 보세요.

---

### 2) 프로그래밍 힌트
* `class Box<T>`와 같이 클래스명 뒤에 `<T>`를 붙여 제네릭을 선언합니다.
* 제네릭 메서드는 `public void PrintInfo<T>(T data)` 처럼 메서드 이름 뒤에 `<T>`를 붙여 정의합니다.
* 제네릭을 사용하면 `int`, `string`뿐만 아니라 직접 만든 `Monster`, `Player` 클래스도 타입으로 전달할 수 있다는 점을 기억하세요.


**[심화 과제 (선택 사항)]**
- **제네릭 제약 조건(Constraints)**: `where T : IDamageable`과 같은 제약 조건을 추가하여, 공격 가능한 대상만 담을 수 있는 전용 보관함을 만들어 보세요.
- **복수 제네릭**: `Pair<T, U>` 클래스를 만들어 서로 다른 두 타입의 데이터를 한 쌍으로 묶어 관리하는 로직을 고민해 보세요. (예: `Pair<Monster, Item>` - 몬스터가 드랍하는 아이템 매칭)
