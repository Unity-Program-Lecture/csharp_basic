# 📝 C# 교육 문서 작성 가이드 (v1.0)
_최종 수정일: 202604131900_

본 가이드는 교육용 C# 문서를 일관성 있고 학습자 친화적으로 작성하기 위한 표준 규칙을 정의합니다. 모든 새로운 교육 문서는 이 규칙을 준수해야 하며, 가이드가 업데이트될 경우 기존 문서도 이에 맞춰 보완합니다.

---

## 1. 파일 관리 규칙
- **저장 위치**: 모든 교육 문서는 `Documents/` 폴더 내에 저장합니다.
- **파일명 규칙**: `[분류]_[주제]_[년월일시분].md` 형식을 사용합니다.
    - 예: `DAY12_CS_ASYNC_202604131900.md`
- **변경 이력**: 문서 구조나 규칙에 큰 변화가 생기면 `Documents/HISTORY.md`에 기록하고, 기존의 `NEXT_STEPS_*.md` 파일들은 히스토리에 통합 후 삭제합니다.

---

## 2. 문서 구조 및 시각적 요소
각 문서는 학습자가 **[목표 확인 -> 개념 이해 -> 실습 미션 파악 -> 코드 확인 -> 퀴즈]** 순서로 학습하도록 구성합니다.

### 🎨 주요 아이콘 사용
- 🚀 **제목/목표**: 문서의 시작과 해당 일차의 학습 목표 제시
- 💡 **개념 설명**: 핵심 용어 정의 및 비유를 통한 쉬운 설명
- 💻 **실습 예제**: 직접 코드를 작성해보는 실습 섹션
- ✍️ **정리/퀴즈**: 학습 내용을 복습하고 스스로 점검하는 단계

---

## 3. 세부 작성 규칙

### 3.1 개념 설명 (💡)
- 전문 용어는 반드시 쉬운 일상 용어로 비유하여 설명합니다.
- "이 단어는 무슨 뜻인가요?"와 같은 문답 형식을 권장합니다.

### 3.2 실습 예제 (💻) - **핵심 규칙**
학습자가 정답 코드를 보기 전에 스스로 생각할 기회를 제공하기 위해 다음 구조를 엄격히 준수합니다.

1. **미션 문구**: `**미션:** `으로 시작하며, 구현해야 할 목표를 한 문장으로 명확히 기술합니다.
2. **코드 접힘**: 모든 C# 예제 코드는 `<details>` 태그를 사용하여 기본적으로 숨깁니다.
3. **태그 구조**:
   ```markdown
   **미션:** [구현 목표 설명]
   <details>
   <summary>코드 보기</summary>

   ```csharp
   // 정답 코드
   ```

   </details>
   ```
   *주의: `<summary>` 태그와 코드 블록(```) 사이에는 반드시 한 줄의 빈 줄이 있어야 합니다.*

### 3.3 복습 퀴즈 (✍️)
- 단순 암기보다는 원리를 이해했는지 묻는 질문을 배치합니다.
- 예: "왜 이 상황에서는 `while` 대신 `for`를 쓰는 것이 좋을까요?"

---

## 4. 가이드 업데이트 프로세스
1. 새로운 작성 방식이나 아이디어가 떠오르면 본 가이드를 먼저 수정합니다.
2. 수정된 버전 번호(v1.x)와 날짜를 갱신합니다.
3. `generalist` 에이전트 등을 활용하여 기존 문서들을 새로운 가이드 규칙에 맞춰 일괄 업데이트합니다.
