# DAY 14: 멀티플레이 테스트 환경과 튜닝

오늘은 "작동한다"를 재현 가능한 테스트 결과로 바꿉니다.

## 1. 핵심 개념: "경기 전 리허설과 기록표"

- **테스트 환경 (Test Environment)**: 동일한 조건에서 기능·오류를 확인하도록 준비한 실행 환경입니다.
- **CBT (Closed Beta Test)**: 제한된 참가자가 기능을 시험하는 단계입니다.
- **OBT (Open Beta Test)**: 더 넓은 참가자에게 공개해 운영 상황을 확인하는 단계입니다.
- **튜닝 (Tuning)**: 측정한 문제를 근거로 수치나 구조를 조정하는 작업입니다.
- **재현 절차 (Reproduction Steps)**: 다른 사람이 같은 오류를 다시 만들 수 있게 적은 순서입니다.

## 2. 안내형 실습: Host/Client 통합 테스트표

**미션:** DAY09~12의 기능을 두 실행 창에서 같은 순서로 검증합니다.

1. `NetworkPlay` 씬을 엽니다.
2. Multiplayer Play Mode를 사용할 수 있으면 패키지가 제공하는 창에서 Player 수를 `2`로 설정합니다. 사용할 수 없으면 Editor에서 Host를 실행하고 별도 Development Build를 Client로 실행합니다.
3. Host를 먼저 시작하고 Client를 연결합니다.
4. 아래 표의 순서대로 실행하고 실제 결과를 적습니다.

| 번호 | 절차 | 기대 결과 | 실제 결과 |
| :--- | :--- | :--- | :--- |
| 1 | Host 시작 | Host Player가 생성된다. |  |
| 2 | Client 연결 | 양쪽에 Player 2개가 보인다. |  |
| 3 | 코인 획득 | 코인이 양쪽에서 한 번 사라지고 점수가 동기화된다. |  |
| 4 | Client 종료 | Host Console에 종료가 기록되고 남은 Player가 유지된다. |  |
| 5 | 다시 연결 | 새 Player가 생성되고 현재 공유 상태를 받는다. |  |

5. 실패한 항목이 있으면 `재현 절차`, `Console 메시지`, `예상 원인`, `수정`, `다시 확인`을 기록합니다.

### 완료 확인

- [ ] Host와 Client 양쪽 결과를 기록했다.
- [ ] 한 번 이상 연결 종료·재연결을 시험했다.
- [ ] 실패가 있으면 재현 절차를 남겼다.

## 응용 실습: 요청 수 비교

DAY07의 10회·100회 요청 테스트를 다시 실행하고, 패킷 크기 또는 전송 빈도를 바꾸기 전후의 성공 수·오류 수·시간을 표로 비교하세요. "좋아졌다" 대신 측정값으로 결론을 쓰세요.
