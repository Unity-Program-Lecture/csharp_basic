# DAY 06: C/S 네트워크 모듈과 패킷 흐름

오늘은 Client/Server 구조에서 수신·처리·표시 책임을 나눕니다.

## 1. 핵심 개념: "접수 창구, 심사실, 안내 전광판"

- **C/S (Client/Server)**: 요청을 보내는 Client와 규칙을 처리하는 Server를 나눈 구조입니다.
- **메시지 경계 (Message Boundary)**: 여러 데이터가 이어져 와도 한 메시지의 시작과 끝을 구분하는 규칙입니다.
- **직렬화 (Serialization)**: 객체 데이터를 전송할 수 있는 문자열 또는 바이트 형태로 바꾸는 작업입니다.
- **역직렬화 (Deserialization)**: 받은 문자열 또는 바이트를 다시 사용할 데이터로 바꾸는 작업입니다.

## 2. 안내형 실습: 줄바꿈 기반 메시지 규약

**미션:** DAY04 채팅을 `TYPE|VALUE` 규약으로 바꿉니다.

1. `PING` 대신 `CHAT|안녕하세요`를 전송합니다.
2. 서버에서 받은 문자열을 `Split('|', 2)`로 나눕니다.
3. 첫 값이 `CHAT`이면 두 번째 값을 출력합니다.
4. 서버는 `SYSTEM|메시지를 받았습니다`를 응답합니다.
5. Client는 응답의 TYPE과 VALUE를 각각 출력합니다.
6. 한 번의 연결에서 두 메시지를 보낼 수 있도록 `while` 반복문 안에서 `ReadLineAsync()`를 호출합니다.

### 완료 확인

- [ ] Client와 Server가 같은 구분자와 메시지 타입을 사용한다.
- [ ] 메시지 타입이 다르면 서로 다른 처리 분기로 들어간다.
- [ ] 빈 줄 또는 알 수 없는 타입을 서버가 오류 없이 거절한다.

## 응용 실습: 이동 요청 추가

`MOVE|3|5` 메시지를 설계하고, Server가 `MOVE_RESULT|3|5`를 돌려주게 만드세요. 서버가 숫자 변환에 실패했을 때 보내는 오류 타입도 정하세요.

## 오늘의 정리

- 네트워크 모듈은 받기만 하는 부품이 아니라, 규약에 맞는지 확인하고 게임 규칙 모듈로 전달하는 경계입니다.
