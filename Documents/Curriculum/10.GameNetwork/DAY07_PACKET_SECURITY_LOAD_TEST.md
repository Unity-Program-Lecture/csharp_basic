# DAY 07: 패킷 설계, 보안, 부하 테스트

오늘은 "보내진다"에서 멈추지 않고, 잘못된 입력·많은 요청·민감한 정보까지 고려합니다.

## 1. 핵심 개념: "입장권 검사와 혼잡한 매표소"

- **검증 (Validation)**: 받은 값이 허용 범위와 규칙에 맞는지 검사하는 작업입니다.
- **암호화 (Encryption)**: 허가되지 않은 사람이 내용을 읽지 못하게 변환하는 방법입니다.
- **부하 테스트 (Load Test)**: 많은 요청을 의도적으로 보내 처리량과 오류를 확인하는 시험입니다.
- **트래픽 (Traffic)**: 네트워크를 오가는 데이터 양과 흐름입니다.

## 2. 안내형 실습: 안전한 이동 패킷 검사

**미션:** Server가 범위를 벗어난 이동 요청을 거절합니다.

1. DAY06의 `MOVE|x|y` 처리를 엽니다.
2. `int.TryParse`로 x, y를 숫자로 바꿉니다.
3. 숫자 변환 실패 시 `ERROR|INVALID_FORMAT`을 보냅니다.
4. x와 y가 `0`부터 `10` 사이인지 검사합니다.
5. 범위를 벗어나면 `ERROR|OUT_OF_RANGE`을 보냅니다.
6. 정상 값만 `MOVE_RESULT|x|y`로 응답합니다.
7. Client에서 `MOVE|99|5`, `MOVE|A|5`, `MOVE|3|5`를 차례로 보냅니다.

### 실행해보면

첫 두 요청은 오류 타입을, 마지막 요청은 정상 결과를 받아야 합니다.

## 3. 보안 설계 메모

비밀번호·인증 토큰·개인 정보는 평문 패킷으로 설계하지 않습니다. 이 수업에서는 직접 암호 알고리즘을 만드는 대신, HTTPS/TLS 같은 검증된 보안 연결을 사용해야 한다는 원칙과 서버 측 검증을 우선 배웁니다.

## 응용 실습: 간단한 부하 측정

Client가 정상 이동 요청을 100번 보내고, 성공·오류 개수와 총 시간을 기록하세요. 요청 수를 10번과 100번으로 바꾼 뒤 결과를 표로 비교하세요.

## 오늘의 정리

- Client가 보낸 값은 신뢰하지 않고 Server가 검증합니다.
- 부하 테스트 결과는 "빨랐다"가 아니라 요청 수, 성공 수, 오류 수, 시간으로 기록합니다.
