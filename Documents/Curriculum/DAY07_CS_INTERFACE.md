# 🚀 Day 07: 추상화와 인터페이스 (강제와 약속)

오늘의 목표는 "**객체를 직접 만들 순 없지만 뼈대가 되는 추상 클래스와, 기능의 약속인 인터페이스의 차이를 이해한다**"입니다.

---

## 1. 추상 클래스(Abstract Class): "미완성 설계도"
공통적인 기능은 미리 만들어두되, 중요한 기능은 자식에게 "너가 직접 완성해!"라고 맡기는 클래스입니다.
- **특징**: `new`로 직접 객체를 만들 수 없습니다.
- **용도**: "동물은 울어야 하지만, 어떻게 울지는(멍멍, 야옹) 동물의 종류마다 다르다" 같은 경우.

---

## 2. 인터페이스(Interface): "기능의 약속"
"이걸 가진 놈이라면 반드시 이 기능을 할 줄 알아야 해!"라고 약속하는 것입니다.
- **특징**: 다중 구현(여러 개의 약속 지키기)이 가능합니다. 변수를 가질 수 없습니다.
- **용도**: "스마트폰이든 컴퓨터든 '충전' 기능은 반드시 있어야 한다."

---

## 🤝 한눈에 비교하기

| 구분 | 추상 클래스 (abstract) | 인터페이스 (interface) |
| :--- | :--- | :--- |
| **핵심** | 부모-자식 (혈연관계) | 기능의 약속 (자격증) |
| **상속/구현** | 단 하나만 상속 가능 | 여러 개 구현 가능 |
| **변수(필드)** | 가질 수 있음 | 가질 수 없음 |
| **비유** | 가문 대대로 내려오는 비법 | 운전면허증 |

---

## 💻 실습 예제: 다중 인터페이스 구현
**미션:** `IMovable`(이동)과 `IAttackable`(공격) 인터페이스를 만들고, 이를 둘 다 가진 `Player` 클래스를 구현해 보세요.

<details>
<summary>코드 보기</summary>

```csharp
using System;

interface IMovable { void Move(); }
interface IAttackable { void Attack(); }

class Player : IMovable, IAttackable // 두 가지 약속을 모두 지킵니다.
{
    public void Move() { Console.WriteLine("플레이어가 걷습니다."); }
    public void Attack() { Console.WriteLine("플레이어가 칼을 휘두릅니다."); }
}

class Program
{
    static void Main()
    {
        Player p = new Player();
        p.Move();
        p.Attack();
    }
}
```

</details>
