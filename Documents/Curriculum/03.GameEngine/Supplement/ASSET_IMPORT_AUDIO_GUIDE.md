# 보충: 사운드 에셋 임포트 가이드

이 문서의 목표는 사운드 파일을 "**게임의 반응을 귀로 알려 주는 신호**"로 이해하고, 파일 포맷의 차이, 사용 용도, Unity Audio Import Settings에서 자주 조정하는 옵션을 정리하는 것입니다.

사운드는 파일을 넣기만 하면 끝나는 자료가 아닙니다. 버튼 클릭음, 공격 효과음, 발소리, 배경음악은 재생 길이와 반복 여부, 메모리 사용 방식이 모두 다릅니다. 같은 소리라도 설정을 잘못하면 시작이 늦거나, 메모리를 많이 쓰거나, 반복 구간이 어색하게 들릴 수 있습니다.

## 1. 핵심 개념: "짧은 소리와 긴 소리는 보관법이 다르다"

효과음은 짧고 자주 재생됩니다. 그래서 버튼음, 공격음, 피격음은 빨리 재생되는 것이 중요합니다. 반대로 배경음악은 길고 계속 흐릅니다. 긴 음악을 전부 메모리에 올리면 프로젝트가 무거워질 수 있으므로 재생 방식과 압축 설정을 다르게 봐야 합니다.

### 이 단어는 무슨 뜻인가요?

- **AudioClip**: Unity가 재생할 수 있도록 임포트한 사운드 데이터입니다.
- **Sample Rate**: 1초에 소리를 얼마나 촘촘하게 기록했는지 나타내는 값입니다.
- **Mono**: 하나의 채널을 쓰는 소리입니다.
- **Stereo**: 왼쪽과 오른쪽 두 채널을 쓰는 소리입니다.
- **Load Type**: 사운드를 메모리에 어떻게 올릴지 정하는 설정입니다.
- **Compression Format**: 사운드 용량을 줄이는 압축 방식입니다.
- **Preload Audio Data**: 씬 시작 시 미리 사운드 데이터를 준비할지 정하는 옵션입니다.

## 2. 자주 쓰는 사운드 파일 포맷

| 포맷 | 특징 | 주 사용 용도 | 주의할 점 |
| :--- | :--- | :--- | :--- |
| `WAV` | 압축이 거의 없고 품질이 높음 | 짧은 효과음 원본, 편집용 원본 | 파일 크기가 큼 |
| `MP3` | 용량이 작고 널리 쓰임 | 배경음악, 임시 음악 자료 | 반복 루프에 공백이 생길 수 있음 |
| `OGG` | 압축 효율이 좋고 게임에서 자주 쓰임 | 배경음악, 긴 환경음 | 플랫폼별 확인 필요 |
| `AIFF` | 고품질 비압축 계열 | 편집용 원본 | 파일 크기가 큼 |

수업 프로젝트에서는 짧은 효과음은 `WAV`, 긴 배경음악은 `OGG`나 `MP3`로 생각하면 이해하기 쉽습니다. 다만 Unity가 임포트 후 내부 압축을 다시 적용할 수 있으므로, 원본 포맷과 Unity Import Settings를 함께 봐야 합니다.

## 3. 용도별 추천 설정 방향

| 용도 | 예시 | 설정 방향 |
| :--- | :--- | :--- |
| UI 효과음 | 버튼 클릭, 확인, 취소 | 빠른 재생 우선, 짧은 클립 |
| 전투 효과음 | 공격, 피격, 폭발 | 짧고 자주 재생되므로 지연이 적게 |
| 발소리 | 걷기, 달리기 | 짧은 클립 여러 개, 약간의 Pitch 변화 |
| 배경음악 | 스테이지 음악, 메뉴 음악 | 긴 클립, 스트리밍 또는 압축 효율 고려 |
| 환경음 | 바람, 물, 기계음 | 반복 재생, 자연스러운 Loop 확인 |
| 음성 | 대사, 안내 음성 | 길이와 플랫폼 용량을 함께 확인 |

## 4. Unity Audio Import Settings에서 자주 보는 옵션

사운드 파일을 Project 창에서 선택하면 Inspector에 Audio Import Settings가 표시됩니다.

| 옵션 | 의미 | 실무에서 보는 기준 |
| :--- | :--- | :--- |
| `Force To Mono` | Stereo를 Mono로 합칠지 정함 | 위치 기반 3D 효과음은 Mono가 유리한 경우가 많음 |
| `Normalize` | Mono 변환 시 소리 크기를 보정 | Force To Mono를 켰을 때 함께 확인 |
| `Load Type` | 오디오 데이터를 메모리에 올리는 방식 | 짧은 효과음과 긴 음악을 다르게 설정 |
| `Preload Audio Data` | 씬 로드시 미리 읽을지 정함 | 즉시 재생해야 하는 효과음은 켜는 경우가 많음 |
| `Compression Format` | 압축 방식 | 품질, 용량, CPU 사용량 균형 |
| `Quality` | 압축 품질 | 낮추면 용량은 줄지만 소리가 손상될 수 있음 |
| `Sample Rate Setting` | 샘플레이트 유지 또는 최적화 | 음질과 용량을 함께 확인 |

설정을 바꾼 뒤에는 `Apply`를 눌러 변경을 적용합니다. 사운드는 눈에 보이지 않기 때문에, 설정 변경 후 반드시 Play Mode에서 직접 들어 봐야 합니다.

## 5. Load Type 이해하기

`Load Type`은 사운드를 언제, 어떻게 준비할지 정합니다. 입문자는 아래처럼 외우면 됩니다.

| Load Type | 쉽게 말하면 | 어울리는 용도 |
| :--- | :--- | :--- |
| `Decompress On Load` | 시작할 때 풀어 두고 빠르게 재생 | 아주 짧고 자주 쓰는 효과음 |
| `Compressed In Memory` | 압축한 채 메모리에 두고 재생 시 처리 | 중간 길이 사운드 |
| `Streaming` | 재생하면서 조금씩 읽음 | 긴 배경음악, 긴 환경음 |

짧은 버튼음을 `Streaming`으로 두면 재생 준비가 불필요하게 복잡해질 수 있습니다. 긴 배경음악을 모두 풀어 메모리에 올리면 메모리를 많이 사용할 수 있습니다. 그래서 사운드 길이에 맞게 Load Type을 나누는 것이 중요합니다.

## 6. 사운드 종류별 설정 예시

### UI 버튼음

```text
Force To Mono: On이어도 대부분 문제 없음
Load Type: Decompress On Load
Preload Audio Data: On
Compression Format: PCM 또는 적당한 압축
```

버튼음은 누르는 순간 바로 들리는 것이 중요합니다. 품질보다 반응 속도와 일관성이 중요하므로 짧고 가볍게 관리합니다.

### 공격 효과음

```text
Force To Mono: 3D 위치 사운드라면 On 고려
Load Type: Decompress On Load 또는 Compressed In Memory
Preload Audio Data: On
Compression Format: ADPCM 또는 Vorbis 등 품질 확인 후 선택
```

공격음은 자주 반복됩니다. 같은 소리를 계속 재생하면 지루할 수 있으므로 여러 클립을 준비하거나 `AudioSource.pitch`를 아주 조금씩 바꾸는 방식도 씁니다.

### 배경음악

```text
Force To Mono: 보통 Off
Load Type: Streaming
Preload Audio Data: 상황에 따라 선택
Compression Format: Vorbis 등 압축 효율 중심
Quality: 직접 들어 보고 조정
```

배경음악은 길이가 길기 때문에 용량과 메모리를 함께 봐야 합니다. 음악이 반복된다면 루프 시작과 끝에 어색한 공백이 없는지도 확인합니다.

### 환경음

```text
Force To Mono: 위치 기반이면 On 고려
Load Type: Compressed In Memory 또는 Streaming
Loop: AudioSource에서 On
Spatial Blend: 2D/3D 용도에 맞게 조정
```

바람, 물, 기계 소리처럼 계속 들리는 환경음은 반복 구간이 자연스러운지가 중요합니다. 파일 자체의 루프 편집과 AudioSource의 `Loop` 설정을 함께 확인합니다.

## 7. 실무에서 자주 생기는 문제

### 1. 소리가 늦게 들림

짧은 효과음이 눌렀을 때 바로 들리지 않으면 조작감이 떨어집니다. 클립 길이 앞부분에 무음이 들어 있거나, `Load Type`, `Preload Audio Data`, 재생 코드 위치가 원인일 수 있습니다.

먼저 오디오 편집 도구에서 파일 앞부분 무음을 제거하고, Unity에서 짧은 효과음이 즉시 재생되도록 설정을 확인합니다.

### 2. 배경음악 루프가 끊김

`MP3` 파일은 인코딩 특성상 루프 앞뒤에 미세한 공백이 생길 수 있습니다. 완전히 자연스러운 반복이 필요하면 루프 편집이 잘 된 원본을 쓰고, Unity에서 반복 재생했을 때 실제로 끊김이 없는지 들어 봅니다.

### 3. 3D 사운드 방향이 이상함

3D 위치 사운드는 AudioSource 위치, Audio Listener 위치, `Spatial Blend`, 거리 감쇠 설정이 함께 영향을 줍니다. UI 버튼음은 2D, 월드 안의 폭발음은 3D에 가깝게 두는 식으로 역할을 나눕니다.

### 4. 프로젝트 용량이 커짐

긴 음악과 음성 파일은 용량을 크게 차지합니다. 사용하지 않는 임시 음악, 고품질 원본, 중복 파일이 프로젝트에 남아 있지 않은지 확인합니다.

### 5. 효과음이 너무 크거나 작음

사운드 파일 자체 볼륨, AudioSource의 `Volume`, Audio Mixer 설정이 함께 영향을 줍니다. 입문 단계에서는 먼저 AudioSource Volume을 맞추고, 프로젝트가 커지면 Audio Mixer로 BGM, SFX, UI 그룹을 나눕니다.

## 8. 추천 폴더 구조

```text
Assets/
  _Project/
    Audio/
      BGM/
      SFX/
      UI/
      Voice/
    Prefabs/
      Audio/
```

사운드는 이름만 보고 용도를 알아보기 어렵기 때문에 폴더 구분이 중요합니다. `button_click_01`, `hit_light_02`, `stage01_bgm_loop`처럼 용도와 번호를 함께 적으면 나중에 찾기 쉽습니다.

## 9. 임포트 체크리스트

| 질문 | 확인할 것 |
| :--- | :--- |
| 짧고 자주 재생되는 효과음인가요? | 빠른 재생 설정과 앞부분 무음 제거 |
| 긴 배경음악인가요? | Streaming, 압축 품질, 루프 공백 확인 |
| UI 사운드인가요? | 2D 사운드로 들리는지 확인 |
| 월드 위치 사운드인가요? | Spatial Blend와 AudioSource 위치 확인 |
| 소리가 너무 큰가요? | 파일 볼륨, AudioSource Volume, Mixer 그룹 확인 |
| 팀원이 알아볼 수 있나요? | BGM/SFX/UI 폴더와 파일명 규칙 확인 |

## 생각해보기

2. UI 버튼음은 3D 위치 사운드보다 2D 사운드가 자연스러운 이유는 무엇일까요?
3. 같은 공격 효과음을 계속 반복하면 왜 어색하게 느껴질까요?

## 오늘의 정리

- 사운드 파일은 길이와 용도에 따라 임포트 설정을 다르게 잡아야 합니다.
- 짧은 효과음은 빠른 재생이 중요하고, 긴 배경음악은 용량과 메모리 관리가 중요합니다.
- `Load Type`, `Preload Audio Data`, `Compression Format`, `Force To Mono`는 자주 확인하는 핵심 옵션입니다.
- UI 사운드, 월드 효과음, 배경음악, 환경음은 재생 방식과 공간감이 다릅니다.
- 사운드는 반드시 Play Mode에서 직접 들어 보며 볼륨, 지연, 반복 구간을 확인해야 합니다.
