# DAY 03: 카메라와 Game View 구성

오늘의 목표는 Unity Camera를 "**게임 화면을 찍는 창**"으로 이해하고, 내가 만든 오브젝트가 Game View에서 어떻게 보이는지 직접 조정하는 것입니다.

## 1. 핵심 개념: "카메라는 플레이어가 보는 창이다"

Scene View는 개발자가 작업하는 화면이고, Game View는 실제 게임을 실행했을 때 플레이어가 보는 화면입니다. 카메라는 Game View에 무엇을 보여 줄지 결정하는 오브젝트입니다.

Unity의 `Main Camera`도 특별한 물건이 아니라 `Camera` Component가 붙은 `GameObject`입니다. 따라서 위치, 회전, 투영 방식, 시야각을 조정하면 같은 장면도 전혀 다르게 보일 수 있습니다.

### 이 단어는 무슨 뜻인가요?

- **Camera**: 게임 화면을 렌더링하는 Component입니다.
- **Game View**: 카메라가 실제로 찍고 있는 결과 화면입니다.
- **Scene View**: 개발자가 오브젝트를 배치하고 확인하는 작업 화면입니다.
- **Projection**: 3D 공간을 화면에 그리는 방식입니다.
- **Perspective**: 멀리 있는 물체가 작게 보이는 원근 투영입니다.
- **Orthographic**: 거리와 상관없이 물체 크기가 일정한 직교 투영입니다.
- **Field of View**: 카메라가 한 번에 볼 수 있는 시야각입니다.
- **Clipping Planes**: 카메라가 그릴 수 있는 가장 가까운 거리와 가장 먼 거리입니다.

## 2. Scene View와 Game View 구분

처음 Unity를 사용할 때는 Scene View에서 오브젝트가 보이는데 Game View에서는 보이지 않는 경우가 많습니다. 이때는 오브젝트가 사라진 것이 아니라 카메라가 해당 오브젝트를 찍고 있지 않은 경우가 많습니다.

| 확인 항목 | 의미 |
| :--- | :--- |
| 카메라 위치 | 카메라가 오브젝트를 볼 수 있는 곳에 있는가 |
| 카메라 회전 | 카메라가 오브젝트 방향을 바라보고 있는가 |
| Field of View | 시야가 너무 좁거나 넓지 않은가 |
| Clipping Planes | 오브젝트가 너무 가깝거나 멀어서 잘리지 않는가 |
| Game View 비율 | 화면 비율 때문에 중요한 부분이 잘리지 않는가 |

## 3. 기본 시점 유형

포트폴리오 초반에는 복잡한 카메라보다 고정 시점부터 안정적으로 구성하는 것이 좋습니다.

| 시점 | 특징 | 적합한 예 |
| :--- | :--- | :--- |
| 정면 시점 | 앞에서 장면을 바라봄 | 2D풍 스테이지, 전시 장면 |
| 사이드뷰 | 옆에서 진행 방향을 봄 | 횡스크롤, 점프 테스트 |
| 탑뷰 | 위에서 아래를 내려다봄 | 미로, 전략, 배치 확인 |
| 쿼터뷰 | 대각선 위에서 장면을 봄 | 탐험, RPG, 퍼즐 공간 |
| 1인칭 시점 | 카메라가 플레이어 눈 위치에 있음 | 시야 체험, VR 준비 |

## 실습 예제: 오브젝트가 잘 보이는 고정 카메라 만들기

**미션:** 큐브와 목표 오브젝트가 Game View에 잘 보이도록 카메라를 배치합니다.

1. 새 씬 또는 기존 실습 씬을 엽니다.
2. 바닥 역할을 할 `Plane`을 하나 만듭니다.
3. `Cube` 3개를 배치해 시작 지점, 중간 장애물, 목표 지점을 만듭니다.
4. `Main Camera`를 선택합니다.
5. `Transform` 값을 조정해 세 오브젝트가 Game View에 모두 보이도록 합니다.
6. `Projection`을 `Perspective`와 `Orthographic`으로 바꿔 보며 차이를 확인합니다.
7. `Field of View` 또는 `Size` 값을 조정해 화면에 보이는 범위를 비교합니다.
8. Play 버튼을 눌러 Game View 기준으로 장면이 잘 보이는지 확인합니다.

### 권장 Transform 예시

쿼터뷰 형태로 시작하려면 다음 값을 참고할 수 있습니다.

```text
Main Camera
Position: X 0, Y 8, Z -8
Rotation: X 45, Y 0, Z 0
Projection: Perspective
Field of View: 60
```

탑뷰 형태로 시작하려면 다음 값을 참고할 수 있습니다.

```text
Main Camera
Position: X 0, Y 10, Z 0
Rotation: X 90, Y 0, Z 0
Projection: Orthographic
Size: 6
```

### 실행해보면

Scene View에서는 자유롭게 장면을 볼 수 있지만, Game View에서는 `Main Camera`가 바라보는 범위만 보입니다. 카메라 위치와 회전을 바꾸면 같은 오브젝트 배치도 전혀 다른 화면 구성으로 보입니다.

### 생각해보기

1. Scene View에는 보이는데 Game View에는 보이지 않는 오브젝트는 어떤 순서로 확인해야 할까요?
2. Perspective와 Orthographic은 각각 어떤 게임에 어울릴까요?
3. 포트폴리오 장면에서 플레이어가 가장 먼저 봐야 하는 오브젝트는 무엇인가요?

## 오늘의 정리

- Camera는 Game View에 무엇을 보여 줄지 결정하는 Component입니다.
- Scene View는 개발자 작업 화면이고, Game View는 플레이어가 보는 화면입니다.
- 카메라의 위치, 회전, 투영 방식, 시야각에 따라 같은 장면도 다르게 보입니다.
- 엔진 과정에서는 카메라를 먼저 안정적으로 배치한 뒤 레벨, 조명, UI를 구성합니다.
