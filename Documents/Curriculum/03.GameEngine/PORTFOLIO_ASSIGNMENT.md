# 게임엔진 응용 프로그래밍 포트폴리오 평가

- 과정: 게임엔진 응용 프로그래밍
- NCS 능력단위: 0803020527_18v4 게임엔진 응용 프로그래밍
- 기준 교재: `NCS_Modules/LM0803020526_18v4_LM0803020527_18v4_게임_알고리즘과_게임엔진_프로그래밍.pdf`
- 평가 방법: 포트폴리오
- 평가 환경: Unity 6, C#, Input System, UGUI, URP
- 권장 범위: 15일차 학습 범위 안에서 완성 가능한 단일 Unity 6 미니 프로젝트

## 과제명

Unity 6 기반 미니 게임엔진 응용 포트폴리오

## 과제 목표

Unity 6 프로젝트 안에서 Scene, GameObject, Component, Transform, Prefab, Physics, UI, Audio/VFX, Package/외부 에셋 관리 흐름을 연결해 작은 플레이 가능한 씬을 완성합니다.

완성도 높은 게임 한 편을 만드는 것이 아니라, 게임엔진의 주요 기능을 이해하고 필요한 컴포넌트를 올바르게 조립할 수 있는지를 확인합니다.

## 제작 주제

다음 중 하나를 선택해 작은 플레이 씬을 제작합니다.

1. 장애물을 지나 목표 지점에 도착하는 3D 미니 코스
2. 아이템을 수집하고 UI에 점수를 표시하는 미니 탐험 씬
3. 버튼, 문, 발판, 효과음이 연결된 간단한 상호작용 씬
4. VR 구조를 모사한 XR Origin 연습 씬 또는 텔레포트 준비 씬

VR 장비가 없는 경우 실제 VR 실행까지 요구하지 않습니다. 이 경우 XR Origin 구조, 컨트롤러 역할 오브젝트, 이동 지점 표시, 상호작용 대상 준비 상태를 Unity 씬에서 확인할 수 있으면 됩니다.

## 필수 구현

1. 프로젝트와 씬 구성
   - Unity 6 프로젝트를 만들고 실행 가능한 씬 1개를 준비합니다.
   - 씬에는 카메라, 조명, 플레이어 역할 오브젝트, 목표 또는 상호작용 대상이 포함되어야 합니다.
   - GameObject의 부모-자식 구조와 Component 구성이 의도에 맞게 정리되어야 합니다.

2. 레벨 프로토타입
   - Plane, Cube, 기본 오브젝트 또는 간단한 Prefab으로 시작점, 이동 경로, 장애물, 목표 지점을 구성합니다.
   - 플레이어가 어디로 이동해야 하는지 Scene View와 Game View에서 확인 가능해야 합니다.
   - 지나치게 넓거나 복잡한 맵보다 수업 시간 안에 테스트 가능한 작은 동선을 우선합니다.

3. 조명과 머티리얼
   - URP Lit 머티리얼을 사용해 최소 3종 이상의 오브젝트 표면을 구분합니다.
   - 색, 금속성, 거칠기, 발광, 조명 중 2개 이상을 의도적으로 조절합니다.
   - 목표 지점, 위험 구간, 상호작용 대상 중 하나는 시각적으로 알아보기 쉽게 표현합니다.

4. 입력과 스크립팅
   - Input System으로 플레이어 이동, 상호작용, 효과 실행 중 하나 이상을 처리합니다.
   - `Update`, `FixedUpdate`, 입력 이벤트의 역할 중 필요한 부분을 구분해 사용합니다.
   - C# 스크립트는 Inspector에서 필요한 참조를 연결할 수 있도록 작성합니다.

5. Prefab과 리소스 관리
   - 반복 배치되는 아이템, 장애물, 효과 오브젝트 중 하나 이상을 Prefab으로 만듭니다.
   - 직접 만든 에셋과 외부 에셋을 폴더상 구분합니다.
   - 외부 에셋을 사용한 경우 출처, 용도, 삭제해도 되는 범위를 설명 문서에 적습니다.

6. 물리와 상호작용
   - Collider, Rigidbody, Trigger, Raycast 중 2개 이상을 사용합니다.
   - 충돌 또는 Trigger를 통해 문 열림, 아이템 획득, 목표 도착, 효과 재생 중 하나 이상의 결과가 발생해야 합니다.
   - 물리 오브젝트가 의도하지 않게 튕기거나 떨어지지 않도록 기본 설정을 점검합니다.

7. UGUI 표시
   - Canvas를 사용해 점수, 남은 아이템 수, 현재 상태, 안내 문구 중 1개 이상을 표시합니다.
   - 화면 크기가 바뀌어도 UI가 크게 무너지지 않도록 Anchor 또는 Canvas Scaler를 확인합니다.
   - Button을 사용하는 경우 클릭 이벤트가 실제 동작과 연결되어야 합니다.

8. 사운드 또는 VFX
   - AudioSource, AudioClip, ParticleSystem 중 1개 이상을 사용합니다.
   - 상호작용, 아이템 획득, 목표 도착, 버튼 클릭 중 하나의 순간에 소리 또는 파티클 반응이 나타나야 합니다.

9. 패키지 또는 외부 기능 확인
   - Package Manager에서 사용한 패키지의 설치 상태를 확인합니다.
   - Input System, XR Interaction Toolkit, Addressables, 외부 에셋 중 사용한 항목을 설명 문서에 적습니다.
   - 사용하지 않은 패키지를 억지로 추가하지 않습니다.

## 선택 구현

선택 구현은 가산 또는 우수 판단 요소로만 봅니다. 필수 구현이 불안정하면 선택 구현보다 필수 구현 안정성을 우선 평가합니다.

1. Addressables 또는 Resources를 이용한 간단한 리소스 로드
2. ScriptableObject를 이용한 아이템 또는 설정 데이터 분리
3. XR Origin과 Teleportation 지점 구성
4. 잡을 수 있는 오브젝트와 물리 Layer 구분
5. 플레이 테스트 결과를 바탕으로 레벨 간격, 카메라 위치, UI 위치 개선
