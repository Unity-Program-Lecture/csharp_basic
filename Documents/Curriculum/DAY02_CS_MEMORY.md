# 🚀 Day 02: 실행 원리와 메모리 (요리사와 조리대)

오늘의 목표는 "**사람이 쓴 코드가 어떻게 하드웨어에서 돌아가는지, 그리고 스택과 힙 메모리가 무엇인지 이해한다**"입니다.

---

## 1. 하드웨어의 삼총사 (무대 설명)
- **CPU (요리사)**: 계산하고 명령을 실행합니다. 오직 '기계어(0, 1)'만 이해합니다.
- **메모리 (조리대)**: 요리 재료와 레시피(코드와 데이터)를 잠시 올려두는 곳입니다.
- **보조기억장치 (창고)**: 프로그램 파일(`.exe`)이 영구 보관되는 곳입니다.

---

## 2. C#의 실행 과정 (번역 단계)
1. **작성**: 사람이 C# 코드를 씁니다.
2. **1차 컴파일**: 어떤 운영체제에서도 돌아가는 표준 레시피(**CIL**)로 바뀝니다.
3. **2차 컴파일 (JIT)**: 실행되는 순간 해당 CPU에 맞는 기계어로 실시간 번역됩니다.

---

## 3. 메모리 구역 (스택 vs 힙)

### 🏢 스택 (Stack): "전용 서랍"
- **특징**: 빠르고 자동입니다. 메소드가 끝나면 서랍을 통째로 비웁니다.
- **담는 것**: 기본 숫자(`int`, `float`), **참조의 주소(보관증)**.

### 🏗️ 힙 (Heap): "대형 창고"
- **특징**: 넓지만 관리가 필요합니다. 청소부(**GC**)가 나중에 치워줍니다.
- **담는 것**: 실제 객체(클래스로 만든 실체), 배열.

---

## 4. 값 vs 참조 (Apple vs TV)
- **값 타입 (Value)**: 변수 안에 진짜 데이터가 있습니다. 복사하면 똑같은 물건이 하나 더 생깁니다.
- **참조 타입 (Reference)**: 변수 안에 **주소**(**리모컨**)가 있습니다. 복사하면 같은 물건을 두 명의 리모컨으로 조종하게 됩니다.

---

## 💻 실습 예제: 리모컨 복사 확인하기
**미션:** 클래스 객체를 복사한 뒤 한쪽의 값을 바꿨을 때 다른 쪽도 바뀌는지 확인해 보세요.

<details>
<summary>코드 보기</summary>

```csharp
using System;

class Monster { public int hp = 100; }

class Program
{
    static void Main()
    {
        // 1. 값 타입 (사과 복사)
        int a = 10;
        int b = a; 
        b = 20;
        Console.WriteLine($"a: {a}, b: {b}"); // 결과: 10, 20

        // 2. 참조 타입 (리모컨 복사)
        Monster m1 = new Monster();
        Monster m2 = m1; // 리모컨만 복사!
        m2.hp = 0;
        Console.WriteLine($"m1 HP: {m1.hp}"); // 결과: 0 (둘 다 바뀜!)
    }
}
```

</details>
