# 과정별 포트폴리오 프로젝트 운영 가이드

이 문서는 `02.Algorithm`, `03.GameEngine`, `04.GameClient` 과정에서 진행하는 포트폴리오 프로젝트의 기본 운영 방향과 과정별 필수 요소를 정리한다. 포트폴리오의 주제, 장르, 그래픽 스타일, 조작 방식, 세부 구현 범위는 학습자가 자유롭게 결정한다. 다만 각 과정 종료 시점에는 해당 과정에서 요구하는 최소 산출 기준을 충족해야 한다.

## 1. 기본 운영 방향

포트폴리오 프로젝트는 하나의 완성형 게임 또는 인터랙티브 콘텐츠를 목표로 한다. 학습자는 과정별로 새 프로젝트를 매번 시작할 수 있으나, 가능하면 이전 과정에서 만든 결과물을 다음 과정에서 보강하는 방식으로 누적 제작하는 것을 권장한다.

각 과정의 포트폴리오 목적은 다음과 같이 구분한다.

| 과정 | 포트폴리오 목적 | 제출 성격 |
| --- | --- | --- |
| `02.Algorithm` | 알고리즘과 문제 해결 구조를 활용한 원시 프로토타입 제작 | 아이디어 검증형 프로토타입 |
| `03.GameEngine` | Unity 엔진 기능을 활용한 장면과 기능 기반 제작 | 게임 엔진 기능 기반 포트폴리오 |
| `04.GameClient` | 입력, 조작, 상호작용, 이벤트 흐름을 갖춘 플레이 경험 완성 | 게임 클라이언트 완성형 포트폴리오 |

동일한 프로젝트를 이어서 제작하는 경우에도 각 과정 종료 시점의 제출물은 독립적으로 확인 가능한 상태여야 한다. 특정 과정의 결과물을 다음 과정에서 보강할 수 있으나, 해당 과정의 제출물이 단순한 미완성 중간 파일로 간주되지 않도록 과정별 필수 요소를 갖추어야 한다.

## 2. 주제 선정 기준

포트폴리오 주제는 자유롭게 정한다. 단, 학습자가 구현 범위를 판단하기 어려운 경우 다음 기준을 우선 적용한다.

1. 짧은 시간 안에 실행 결과를 확인할 수 있는 주제를 선택한다.
2. 한 화면 또는 한 씬에서 핵심 기능을 설명할 수 있는 구조를 우선한다.
3. 거대한 세계관이나 많은 스테이지보다 작은 플레이 루프를 우선한다.
4. 수업에서 배운 기능이 프로젝트 안에서 실제로 드러나야 한다.
5. 무료 에셋을 사용할 수 있으나, 프로젝트 구조와 기능 구현 의도를 설명할 수 있어야 한다.

권장 예시는 다음과 같다.

- 간단한 3D 탐험 또는 탈출 콘텐츠
- 아이템을 수집하고 목표 지점에 도착하는 미니 게임
- 장애물을 피하거나 장치를 작동시키는 퍼즐형 콘텐츠
- 알고리즘 프로토타입을 Unity 장면으로 확장한 콘텐츠
- 상호작용 오브젝트와 UI 피드백이 포함된 짧은 게임 시연물

위 예시는 참고용이며, 동일한 형태로 제작할 필요는 없다.

## 3. `02.Algorithm` 과정 포트폴리오 기준

`02.Algorithm` 과정의 포트폴리오는 게임 아이디어를 매우 단순한 형태로 검증하는 원시 프로토타입으로 본다. 이 단계에서는 그래픽 완성도보다 문제 해결 방식, 규칙 처리, 데이터 흐름, 반복 실행 구조가 드러나는 것을 우선한다.

### 필수 요소

1. 실행 가능한 프로그램 또는 시연 가능한 결과물이 있어야 한다.
2. 조건문, 반복문, 배열 또는 컬렉션 중 일부가 실제 기능에 사용되어야 한다.
3. 게임 규칙, 점수, 상태 변화, 경로 탐색, 충돌 판정, 턴 진행 중 하나 이상의 알고리즘적 요소가 포함되어야 한다.
4. 사용자가 입력하거나 결과를 확인할 수 있는 흐름이 있어야 한다.
5. 프로젝트의 목적과 실행 방법을 간단히 설명할 수 있어야 한다.

### 후속 과정 연계

`02.Algorithm` 과정에서 제작한 프로토타입은 희망자에 한해 `03.GameEngine` 및 `04.GameClient` 과정의 포트폴리오로 이어서 발전시킬 수 있다. 단, 이후 과정에서 제출할 때에는 단순히 기존 결과물을 유지하는 것이 아니라 해당 과정의 필수 요소를 새롭게 충족해야 한다.

## 4. `03.GameEngine` 과정 포트폴리오 기준

`03.GameEngine` 과정의 포트폴리오는 Unity 엔진 기능을 활용하여 장면과 기본 기능을 구성하는 것을 목적으로 한다. 이 단계에서는 완성된 게임 플레이보다 Unity 프로젝트 구조, 씬 구성, 에셋 적용, 시각 및 청각 요소, 기본 상호작용 기능이 확인되어야 한다.

### 필수 요소

1. Unity 프로젝트와 실행 가능한 씬이 구성되어 있어야 한다.
2. `GameObject`, `Hierarchy`, `Component` 구조가 의도에 맞게 정리되어 있어야 한다.
3. 간단한 레벨, 공간, 스테이지, 실습 장면 중 하나가 구성되어 있어야 한다.
4. 카메라를 배치하고 Game View에서 주요 공간과 오브젝트가 확인되도록 구성해야 한다.
5. 조명과 머티리얼을 적용하여 장면의 분위기 또는 구역 구분이 드러나야 한다.
6. 프로젝트에 사용한 리소스 또는 에셋이 폴더 구조 안에서 정리되어 있어야 한다.
7. Character Controller 또는 Navigation 시스템을 사용해 이동 관련 기능을 확인할 수 있어야 한다.
8. Animation 또는 Animator, UI, 사운드, VFX, 물리 Trigger 중 최소 2개 이상의 요소가 실제 기능으로 적용되어야 한다.
9. 실행했을 때 사용자가 결과를 확인할 수 있는 프로토타입 상태여야 한다.

### 권장 요소

1. 시작 지점과 목표 지점이 구분된 간단한 공간을 구성한다.
2. 문, 버튼, 발판, 수집물 등 기능을 확인할 수 있는 오브젝트를 배치한다.
3. UI는 상태 표시, 안내 문구, 진행 결과 표시 중 하나 이상의 역할을 담당하도록 한다.
4. 애니메이션, 사운드, VFX는 장식용 배치보다 이동이나 사용자 행동에 대한 피드백으로 사용하는 것을 우선한다.
5. 외부 에셋을 사용하는 경우 원본과 수정 리소스를 구분하여 관리한다.

### 제외 또는 후순위 요소

`Input System`을 활용한 본격적인 입력 구조, 플레이어 조작, 캐릭터 상태 처리, 게임플레이 이벤트 흐름은 `04.GameClient` 과정에서 본격적으로 다룬다. `03.GameEngine` 과정에서 간단한 이동이나 테스트용 입력을 사용할 수는 있으나, 해당 요소를 핵심 필수 요건으로 보지 않는다.

## 5. `04.GameClient` 과정 포트폴리오 기준

`04.GameClient` 과정의 포트폴리오는 사용자가 직접 조작하고 목표를 달성할 수 있는 게임 클라이언트 형태로 완성하는 것을 목적으로 한다. 이 단계에서는 `03.GameEngine` 과정에서 구성한 장면과 기능을 바탕으로 입력, 조작, 상태 변화, 상호작용, 이벤트 흐름을 연결한다.

### 필수 요소

1. `Input System`을 사용하여 입력 구조를 구성해야 한다.
2. 입력 결과가 캐릭터, 카메라, 오브젝트 이동, 선택, 상호작용 중 하나 이상의 조작으로 연결되어야 한다.
3. 캐릭터 또는 조작 대상의 상태 변화가 있어야 한다.
4. Cinemachine을 사용해 플레이어 또는 조작 대상을 보조하는 카메라를 구성해야 한다.
5. 플레이어가 상호작용할 수 있는 대상이 있어야 한다.
6. 아이템, 이벤트, 목표 달성, 결과 표시 중 하나 이상의 게임 흐름이 포함되어야 한다.
7. 시작, 진행, 종료 또는 결과 확인이 가능한 플레이 루프가 있어야 한다.
8. 시연 또는 빌드 가능한 상태로 제출해야 한다.

### 권장 요소

1. 플레이어 조작은 단순 이동에 그치지 않고 상호작용 또는 목표 달성과 연결되도록 한다.
2. Cinemachine Virtual Camera를 사용해 추적, 시점 전환, 줌, 블렌드 중 필요한 기능을 구성한다.
3. UI는 현재 상태, 보유 아이템, 목표, 결과 중 하나 이상을 표시하도록 한다.
4. 이벤트는 단순 출력보다 오브젝트 변화, 문 열림, 점수 변화, 목표 갱신 등 실제 플레이 변화로 연결한다.
5. 게임 클라이언트 구조를 설명할 수 있도록 주요 스크립트와 오브젝트 이름을 정리한다.
6. 시연 순서를 사전에 정리하여 제출 시 기능 확인이 가능하도록 한다.

## 6. 제출 형태

각 과정 종료 시점에는 다음 자료를 제출 가능한 상태로 정리한다.

1. 실행 가능한 프로젝트 폴더 또는 빌드 결과물
2. 프로젝트 설명 문서
3. 주요 기능 목록
4. 조작 방법 또는 시연 방법
5. 사용한 외부 에셋 또는 참고 자료 목록
6. 현재 구현된 내용과 이후 보강 가능한 내용 구분

프로젝트 설명 문서에는 다음 내용을 포함하는 것을 권장한다.

```text
프로젝트명:
제작자:
과정명:
프로젝트 개요:
주요 기능:
조작 방법:
사용한 기술 요소:
사용한 에셋 또는 참고 자료:
미구현 또는 보강 예정 사항:
```

## 7. 운영 유의 사항

포트폴리오 프로젝트는 학습자의 개별 선택을 존중하되, 과정별 필수 요소를 충족하는 범위 안에서 운영한다. 강사는 모든 학습자에게 동일한 장르나 동일한 결과물을 요구하기보다, 각 프로젝트가 해당 과정의 학습 목표를 드러내는지 확인한다.

특히 다음 사항을 유의한다.

1. 주제와 장르는 자유롭게 허용한다.
2. 기능 규모보다 실행 가능성과 설명 가능성을 우선한다.
3. 외형 완성도보다 수업에서 배운 구조와 기능이 드러나는지를 우선한다.
4. 이전 과정 결과물을 이어서 사용하는 것은 허용하되, 현재 과정의 필수 요소를 추가로 충족해야 한다.
5. 과정 종료 제출물은 해당 시점에서 독립적으로 시연 가능한 상태여야 한다.

## 8. 과정별 정리

`02.Algorithm` 과정은 아이디어와 규칙을 검증하는 단계이다. `03.GameEngine` 과정은 Unity 엔진 기능을 활용하여 장면과 기본 기능을 구성하는 단계이다. `04.GameClient` 과정은 사용자가 직접 조작하고 목표를 달성할 수 있는 클라이언트 형태로 완성하는 단계이다.

따라서 전체 포트폴리오 운영은 하나의 프로젝트를 누적해서 발전시키는 방향을 권장하되, 각 과정 종료 시점에는 해당 과정의 필수 요소를 갖춘 독립 제출물로 관리한다.
