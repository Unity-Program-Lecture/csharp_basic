# 게임 데이터베이스 프로그래밍 운영 계획

이 문서는 `26국기_교수계획서.pdf`의 `0803020532_18v4 게임 데이터베이스 프로그래밍` 45시간을 Unity 6과 C#으로 재구성한 학생 공개용 운영표입니다. 추석 연휴가 있는 이번 운영에서는 **1~7일차에 핵심 실습을 압축 진행**하고, **8일차에 통합 점검과 능력단위 평가**를 진행합니다. 학습 문서는 실제 수업일과 같은 `DAY01`~`DAY08` 번호를 사용하며, 한 날의 전·후반 내용은 하나의 문서에 연속 교시로 통합합니다.

## 운영 원칙

- 관계형 DB는 SQLite와 SQL로, NoSQL의 문서형 DB는 LiteDB와 C# API로 각각 확인합니다. 키-값형 Redis, 컬럼형 Apache Cassandra, 그래프형 Neo4j는 분류와 대표 제품만 확인합니다.
- 1일차에서 만든 `GameShop.db`를 3일차에서 SQL CRUD·트랜잭션으로 확장하고, 4~5일차에서 C# 관리 프로그램과 자동 롤백 처리로 다시 구성합니다.
- Unity 6에서는 DB를 직접 운영하는 대신, 읽기 전용 기획 DB와 실행 중 저장 DB의 책임을 구분해 화면 표시를 실습합니다.
- 모든 DAY에는 안내형 실습, 완료 확인, 조건만 제시하는 응용 실습을 둡니다.
- 공개 문서는 학습과 자기 점검용이며, 평가 문항과 채점 기준은 별도 비공개 자료로 관리합니다.
- 압축 운영에서는 이미 학습한 SQL 문법, PK·FK 정의, CRUD 정의, 문서형 NoSQL 정의를 다시 강의하지 않습니다. 이후 모듈은 새 API·새 실습 결과에 집중하고, 앞 모듈 링크로만 복습합니다.

## 공통 실습 결과 확인 규칙

DB 실습은 Console 메시지만 보고 통과로 판단하지 않습니다. SQL 또는 C# 실행 결과와 DB Browser의 실제 행, Unity 실습에서는 화면·Inspector·Console을 함께 확인합니다. 오류가 나면 `증상 → 오류 메시지 → 사용한 DB 파일 경로 → 실행한 SQL 또는 코드 흐름` 순서로 기록합니다.
