오늘은 게임 데이터베이스 설계, 관계형·문서형 관리 프로그램, 트랜잭션, 롤백, 유지보수 문서를 하나의 흐름으로 점검합니다.

## NCS 연결

- 능력단위: `0803020532_18v4 게임 데이터베이스 프로그래밍`
- 능력단위 요소: 게임 데이터베이스 응용 프로그래밍하기
- 주요 학습 내용: 트랜잭션, 롤백, 유지보수 문서 작성

## 1. 통합 시나리오: 포션 구매

```text
1. Player와 Item, Inventory를 설계한다.
2. SQLite에서 골드와 인벤토리를 관리한다.
3. LiteDB에 구매 성공 또는 실패 로그를 남긴다.
4. Unity UI는 결과 골드와 포션 수량을 표시한다.
5. 오류가 나면 SQLite 트랜잭션을 롤백하고 실패 로그를 남긴다.
```

## 2. 통합 테스트표

| 번호 | 시나리오 | 기대 결과 | 확인 위치 |
| :--- | :--- | :--- | :--- |
| 1 | 골드 100으로 포션 구매 | 골드 70, 포션 1 | SQLite와 Unity UI |
| 2 | 골드 10으로 포션 구매 | 골드 10, 포션 증가 없음 | SQLite와 콘솔 메시지 |
| 3 | 잘못된 ItemId로 구매 | 모든 변경 롤백 | SQLite |
| 4 | 구매 성공 | 성공 로그 문서 생성 | LiteDB |
| 5 | 구매 실패 | 실패 이유가 있는 로그 문서 생성 | LiteDB |
| 6 | 프로그램 재실행 | 이전 데이터가 다시 조회됨 | DB 파일 |
