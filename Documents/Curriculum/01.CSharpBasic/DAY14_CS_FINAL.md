## 1. 비동기 (Async/Await): "기다리는 동안 딴짓하기"
동기(Synchronous) 방식은 한 작업이 끝날 때까지 다음 줄로 넘어가지 못합니다. 비동기(Asynchronous) 방식은 시간이 걸리는 작업을 예약해두고 다른 일을 먼저 처리할 수 있게 해줍니다.

- **`async`**: 이 함수는 비동기적으로 실행될 것임을 알립니다.
- **`await`**: "이 작업이 끝날 때까지 여기서 잠시 기다려줘"라고 말합니다. (하지만 프로그램 전체가 멈추는 것은 아닙니다!)
- **`Task`**: 비동기 작업의 단위입니다.

```csharp
using System.Threading.Tasks;

// 비동기 함수 정의
async Task DoSomethingAsync() 
{
    // 1초 동안 기다림 (프로그램은 멈추지 않음)
    await Task.Delay(1000); 
    Debug.Log("비동기 작업 완료!");
}
```

### 💡 비동기의 동작 원리: "끼어들기"가 아닌 "줄 서기"
많은 분들이 `await`가 끝나면 갑자기 다른 코드 실행 중에 비동기 코드가 튀어나온다고 오해합니다. 하지만 C#의 비동기는 매우 질서 정연하게 동작합니다.

1. **상태 저장 (일시 정지)**: `await`를 만나면 함수는 "나중에 여기서부터 다시 시작할게"라고 메모를 남기고, 자신을 부른 곳으로 일단 돌아갑니다.
2. **컨텍스트 캡처 (환경 기억)**: 이때 "나는 메인 스레드(유니티의 메인 루프)에서 실행 중이었어"라는 정보를 기억해 둡니다.
3. **복귀 대기 (차례 기다리기)**: 비동기 작업(예: 로딩)이 끝나면 곧바로 실행되는 게 아니라, **메인 스레드에 "나 이제 다음 줄 실행해도 돼?"라고 신호**를 보냅니다.
4. **질서 있는 재개**: 유니티 엔진은 현재 실행 중인 함수나 프레임 처리가 완전히 끝난 뒤, **안전한 타이밍에 `await` 다음 줄을 실행**시켜 줍니다.

> **결론**: 비동기 코드는 다른 함수를 실행 도중에 끊고 들어오는 '무법자'가 아니라, 자기 순서를 기다려 복귀하는 '매너 있는 일꾼'입니다.

## 💻 실습 예제: 네트워크 데이터 로딩 시뮬레이션
```csharp
using UnityEngine;
using System.Threading.Tasks;

public class Day14_Practice : MonoBehaviour
{
    async void Start()
    {
        Debug.Log("게임 리소스를 불러오기 시작합니다...");

        // 2초 동안 가상의 로딩 작업을 수행합니다.
        await LoadResourcesAsync();
        
        Debug.Log("모든 리소스 로딩 완료! 게임을 시작합니다.");
    }

    async Task LoadResourcesAsync()
    {
        // 실제로는 네트워크 다운로드나 무거운 계산이 들어가는 곳입니다.
        await Task.Delay(2000); // 2000ms(2초) 동안 비동기로 대기
        Debug.Log("...몬스터 데이터를 분석 중...");
        
        await Task.Delay(1000); // 추가 1초 대기
        Debug.Log("...맵 타일 배치 중...");
    }
}
```
