# 게임 클라이언트 포트폴리오 과제

- 대상 과정: `04.GameClient`
- 평가 환경: Unity 6, C#, Input System
- 권장 범위: 학습 시간 안에 완성 가능한 단일 Unity 6 미니 게임 또는 인터랙티브 콘텐츠
- 연계 방식: `03.GameEngine` 과정 결과물을 이어서 제작하는 것을 권장함

## 과제명

Unity 게임 클라이언트 완성형 포트폴리오 제작

## 과제 목표

Unity 6 프로젝트 안에서 `Input System`, 플레이어 조작, 캐릭터 상태, 상호작용, 아이템 또는 이벤트 흐름을 연결해 사용자가 직접 플레이할 수 있는 게임 클라이언트 포트폴리오를 제출합니다.

이 과제는 장면 구성만 확인하는 프로토타입이 아니라 시작, 진행, 결과 확인이 가능한 플레이 루프를 요구합니다.

## 필수 구현

1. Input System 기반 입력 처리

   Unity `Input System`을 사용해 키보드, 마우스, 게임패드 중 하나 이상의 입력을 처리합니다. 입력 설정과 스크립트 연결 관계를 설명할 수 있어야 합니다.

2. 플레이어 또는 조작 대상 제어

   입력 결과가 캐릭터, 카메라, 오브젝트 이동, 선택, 상호작용 중 하나 이상의 조작으로 연결되어야 합니다. 사용자가 실행 중에 조작 결과를 직접 확인할 수 있어야 합니다.

3. 상태 변화 구현

   캐릭터 또는 조작 대상의 상태 변화가 있어야 합니다. 예를 들어 대기, 이동, 상호작용, 획득, 성공, 실패, 비활성화 등의 상태를 사용할 수 있습니다.

4. Cinemachine 카메라 구성

   Cinemachine을 사용해 플레이어 또는 조작 대상을 따라가는 카메라를 구성합니다. `Follow`, `Look At`, Virtual Camera, Cinemachine Brain의 역할을 설명할 수 있어야 합니다.

5. 상호작용 대상 구현

   플레이어가 접근하거나 입력을 통해 반응시킬 수 있는 오브젝트를 구현합니다. 상호작용 결과는 화면, 오브젝트, UI, 사운드, 이벤트 중 하나 이상으로 확인되어야 합니다.

6. 게임 흐름 구현

   아이템, 이벤트, 목표 달성, 결과 표시 중 하나 이상의 게임 흐름을 구현합니다. 기능이 개별적으로만 존재하지 않고 플레이 순서 안에서 연결되어야 합니다.

7. 플레이 루프 구성

   시작, 진행, 종료 또는 결과 확인이 가능한 플레이 루프를 구성합니다. 짧은 미니 게임 형태여도 무방하나, 사용자가 무엇을 해야 하는지와 결과가 무엇인지 확인할 수 있어야 합니다.

8. 시연 또는 빌드 가능 상태

   프로젝트는 시연 가능한 상태여야 합니다. 제출 시 주요 기능을 확인할 수 있는 씬, 조작 방법, 시연 순서를 함께 제시합니다.

## 선택 구현

다음 항목은 필수는 아니지만 프로젝트 완성도를 높이기 위해 권장합니다.

1. Cinemachine을 활용한 시점 전환, 줌, 카메라 블렌드
2. 인벤토리, 점수, 체력, 진행도 등 상태를 표시하는 UI
3. 아이템 획득, 문 열림, 목표 갱신, 결과 표시 등 이벤트 흐름
4. 사운드와 VFX를 활용한 행동 피드백
5. `03.GameEngine` 과정에서 만든 장면과 리소스의 보강

## 유의 사항

`03.GameEngine` 과정에서 만든 프로젝트를 이어서 제작하는 경우에도 본 과정의 필수 구현 요소를 충족해야 합니다. 장면 구성, 조명, 머티리얼, 리소스 배치가 이미 되어 있더라도 입력, 조작, 상태, 상호작용, 게임 흐름이 새롭게 확인되어야 합니다.

주제와 장르는 자유롭게 선택할 수 있습니다. 다만 제출물은 사용자가 직접 조작하고 결과를 확인할 수 있는 형태여야 합니다.
