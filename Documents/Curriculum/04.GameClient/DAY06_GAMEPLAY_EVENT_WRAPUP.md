# DAY 06: 게임플레이 이벤트와 클라이언트 정리

오늘의 목표는 게임플레이 이벤트를 "**게임 안에서 벌어진 일을 다음 행동으로 넘기는 신호**"처럼 이해하고, 6일 동안 만든 클라이언트 요소를 작은 미니 과제로 묶는 것입니다.

## 1. 핵심 개념: "게임은 이벤트가 이어지는 흐름이다"

플레이어가 이동하고, 상자를 열고, 아이템을 얻고, 목표 지점에 도착하면 게임은 다음 반응을 실행합니다. 이런 반응의 연결을 게임플레이 이벤트라고 볼 수 있습니다. 이벤트를 잘 나누면 한 기능이 다른 기능을 직접 붙잡지 않아도 흐름을 이어 갈 수 있습니다.

클라이언트 과정의 마지막 날에는 새 기술을 많이 늘리기보다 입력, 캐릭터 상태, 상호작용, 지형 확인, 아이템 이벤트가 하나의 작은 플레이 흐름으로 이어지는지 점검합니다.

### 이 단어는 무슨 뜻인가요?

- **Gameplay Event**: 게임 플레이 중 발생한 일을 알리는 신호입니다.
- **Reward**: 플레이어 행동의 결과로 주어지는 보상입니다.
- **Objective**: 플레이어가 달성해야 하는 목표입니다.
- **Flow**: 입력부터 결과까지 이어지는 실행 순서입니다.
- **Wrap-up**: 배운 내용을 정리하고 작은 결과물로 묶는 단계입니다.

## 2. 미니 클라이언트 점검표

| 항목 | 확인 질문 |
| :--- | :--- |
| 입력 | 이동과 상호작용 입력이 분리되어 있나요? |
| 캐릭터 | 이동, 회전, 상태 변화가 눈에 보이나요? |
| 상호작용 | 가까운 대상만 실행되나요? |
| 월드 | 이동 가능한 영역과 막힌 영역을 구분했나요? |
| 아이템 | 획득, 보관, 사용 흐름이 있나요? |
| 이벤트 | 목표 달성이나 보상 메시지가 표시되나요? |

## 실습 예제: 목표 지점 도착 이벤트 만들기

**미션:** 플레이어가 목표 지점 Trigger에 들어오면 보상 이벤트를 실행합니다.

1. 목표 지점 오브젝트를 만들고 Collider의 `Is Trigger`를 켭니다.
2. 목표 지점에 아래 스크립트를 붙입니다.
3. 플레이어 오브젝트에는 `Player` 태그를 지정합니다.

<details>
<summary>코드 보기</summary>

```csharp
using UnityEngine;

public class GoalRewardEvent : MonoBehaviour
{
    [SerializeField] private int rewardGold = 100;

    private bool isCompleted;

    void OnTriggerEnter(Collider other)
    {
        if (isCompleted || !other.CompareTag("Player"))
        {
            return;
        }

        isCompleted = true;
        GiveReward();
        Debug.Log("목표 지점에 도착했습니다. 클라이언트 미션 완료!");
    }

    private void GiveReward()
    {
        Debug.Log($"보상 지급: Gold +{rewardGold}");
    }
}
```

</details>

### 실행해보면

플레이어가 목표 지점에 들어가면 보상 메시지가 한 번만 출력됩니다. `isCompleted`가 있기 때문에 같은 Trigger에 다시 들어가도 보상이 반복 지급되지 않습니다.

### 생각해보기

1. 보상 이벤트가 여러 번 실행되면 게임 밸런스에 어떤 문제가 생길까요?
2. 목표 지점 도착, 상자 열기, 아이템 사용은 어떤 공통 구조를 가지고 있을까요?

## 오늘의 정리

- 게임플레이 이벤트는 플레이어 행동과 게임 반응을 이어 주는 신호입니다.
- 클라이언트 기능은 입력, 캐릭터, 상호작용, 월드, 아이템, 이벤트 흐름으로 묶어 점검할 수 있습니다.
- 최종 미니 과제는 큰 게임 완성이 아니라 작은 기능들이 끊기지 않고 이어지는지 확인하는 데 집중합니다.
