# 게임플랫폼 포트폴리오 제출

## 1. 제출 대상

개인이 제작한 Unity 프로젝트와 프로젝트 소개 문서를 제출한다. 수업의 PlatformCoinLab 또는 이번 과정의 필수 요소를 갖춘 자신의 프로젝트를 제출할 수 있다. 게임 장르와 클래스 이름은 제한하지 않는다.

Unity 기준 버전은 `6000.6.7f1`이며, PC (Windows)·Android·Web의 빌드와 실행 결과를 제출한다. iOS는 제출 대상에서 제외한다.

## 2. 프로젝트 필수 요소

- 플랫폼별 요구사항에 맞는 입력·화면·저장·성능 설정과 라이브러리 활용.
- 게임에 필요한 자료 구조와 시작·진행·종료·재시작 흐름.
- PC 입력과 Android 터치 입력, 화면 비율·Safe Area 대응.
- 데이터 저장·재실행, 앱 중단·복귀 처리, 효과음 재생.
- Editor 전용 코드와 Player 코드의 분리 및 필요한 플랫폼별 처리.
- Addressables를 이용한 비동기 자산 로드·실패 안내·재시도·해제.
- ASP.NET Core HTTPS 파일 서버를 통한 콘텐츠 제공과 실패·복구 확인.
- JSON 설정의 검증·적용 및 읽기 실패 시 기본값 처리.
- 플랫폼별 Player 실행, 오류 재현·수정·재검증, 실제 Player의 프로파일 분석과 최적화 전후 비교.

자신의 프로젝트를 제출하는 경우 각 요소를 게임에 맞는 기능으로 구현한다. 코인 개수나 제한 시간 등 수업 예제의 수치를 그대로 적용할 필요는 없다. 기본 게임은 서버 없이 실행할 수 있도록 구성하고, 원격 콘텐츠·설정 비교 절차는 별도로 안내한다.

## 3. 제출 파일

| 구분 | 제출 내용 |
| :--- | :--- |
| Unity 프로젝트 | Assets와 모든 .meta 파일, Packages, ProjectSettings |
| PC 빌드 | 실행 파일과 Data 폴더 등 생성된 출력 전체 |
| Android 빌드 | 설치 가능한 APK |
| Web 빌드 | HTML·Build·TemplateData 등 생성된 출력 전체 |
| 파일 서버 | ContentServer 소스, 필요한 콘텐츠·설정 파일, 콘텐츠 생성·배포 및 서버 실행 절차 |
| 프로젝트 소개 문서 | 아래 구성요소를 포함한 Markdown·PDF·웹 문서 중 하나 |
| 확인 자료 | 대표 이미지, 플레이 영상, 오류 해결 자료, 수정 전후 Profiler 캡처 |

Unity 프로젝트의 Library·Temp·개인 IDE 캐시와 서버의 bin·obj는 제외한다. 서명 키·비밀번호·토큰·인증서 개인키·개인 장치 정보는 포함하지 않는다. 소스·빌드·영상·소개 문서는 같은 제출 버전을 기준으로 준비한다.

## 4. 프로젝트 소개 문서 구성

| 구성요소 | 작성 내용 |
| :--- | :--- |
| 프로젝트 소개 | 게임 이름·장르·대상 플랫폼·핵심 플레이 |
| 개발 정보 | 제작자·개발 기간·Unity 및 주요 패키지 버전 |
| 실행 자료 | 대표 이미지·플레이 영상·실행 파일과 소스의 위치 |
| 주요 구현 기능 | 기능의 목적·구현 방식·자료 구조와 처리 순서·핵심 코드 위치 |
| 플랫폼 대응 | 플랫폼별 입력·화면·저장·생명주기·콘텐츠 처리와 실행 결과 |
| 추가·개선한 부분 | 수업 구현과의 차이·필요한 이유·구현 방법·동작 결과 |
| 문제 해결 사례 | 실제 문제와 재현 조건·원인·수정 내용·재검증 결과 |
| 성능 개선 | 측정 환경·변경 내용·수정 전후 값·기능 유지 여부·측정 한계 |
| 실행·복원 방법과 한계 | 시작 씬·조작법·콘텐츠 및 Player 빌드 순서·서버 실행 방법·알려진 문제·미확인 환경 |

수업에서 따라 구현한 부분, 외부 자료를 활용한 부분, 직접 추가·개선한 부분을 구분한다. 기능 확장이 없는 경우 수업 기본 구현만 완료한 것으로 표시한다. 외부 코드와 자산은 출처와 사용 범위를 명시한다.

기능 설명은 `무엇을 구현했는가 → 왜 필요한가 → 어떻게 구현했는가 → 실행 결과` 순서로 작성한다. 코드 전체를 붙이는 대신 핵심 파일·메서드와 관련 이미지·영상 구간을 연결한다. 실제 문제 해결 사례와 동일 조건의 최적화 전후 비교를 각각 하나 이상 포함한다. 수업에서 재현·개선한 사례를 사용할 수 있으며 그 사실을 표시한다.

## 5. 확인 자료와 실행 준비

- 기본 플레이와 직접 추가·개선한 기능을 영상에서 확인할 수 있도록 구성한다. 제출 후 실행 시연과 핵심 코드 설명이 가능하도록 준비한다.
- 기존 실습 기록의 로그·영상·Profiler 캡처를 소개 문서에 첨부하거나 연결한다. 별도의 확장 보고서나 NCS 항목별 보고서는 요구하지 않는다.
- 파일과 문서 링크는 별도 로그인이나 편집 권한 없이 평가자가 열람할 수 있도록 준비한다. 확인 자료는 링크 대신 파일로 제출할 수 있다.
- 실행하지 못한 환경과 측정하지 못한 항목은 미확인·미측정으로 표시하고 보완 계획을 기재한다. Android 실기기와 에뮬레이터 결과를 구분하며, 교사 시연을 본인의 실행 결과로 작성하지 않는다.
