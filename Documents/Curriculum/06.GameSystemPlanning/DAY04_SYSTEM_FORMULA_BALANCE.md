# DAY 04: 시스템 공식과 밸런스 기준

오늘은 시스템에서 숫자가 어떻게 계산되는지 정리합니다. 공식은 수학을 어렵게 만들기 위한 것이 아니라, 같은 상황에서 같은 결과가 나오도록 약속을 만드는 도구입니다.

## 1. 핵심 개념: "요리 레시피의 계량"

김치찌개를 만들 때 "대충 맛있게"라고만 적으면 사람마다 결과가 달라집니다. 물 500ml, 고춧가루 1스푼, 10분 끓이기처럼 기준을 적어야 비슷한 맛을 낼 수 있습니다.

게임 공식도 비슷합니다. "강한 몬스터는 경험치를 많이 준다"보다 "경험치 = 기본 경험치 + 몬스터 레벨 x 5"처럼 쓰면 개발자와 기획자가 같은 결과를 예상할 수 있습니다.

### 이 단어는 무슨 뜻인가요?

- **공식**: 입력값을 계산해 결과값을 만드는 규칙입니다.
- **밸런스**: 너무 쉽거나 어렵지 않게 수치의 관계를 맞추는 일입니다.
- **기준값**: 계산의 출발점이 되는 기본 수치입니다.
- **변수**: 상황에 따라 달라지는 값입니다.
- **상한/하한**: 결과값이 너무 커지거나 작아지지 않도록 정한 범위입니다.

## 2. 처음 공식은 단순해야 한다

입문 단계의 시스템 공식은 복잡할 필요가 없습니다. 중요한 것은 "무엇이 결과에 영향을 주는가"를 분명히 하는 것입니다.

| 시스템 | 간단 공식 예시 |
| :--- | :--- |
| 피해량 | 최종 피해 = 공격력 - 방어력 |
| 판매 가격 | 판매 가격 = 기본 가격 x 희귀도 배율 |
| 경험치 | 획득 경험치 = 기본 경험치 + 적 레벨 x 5 |
| 성공 확률 | 성공 확률 = 기본 확률 + 적합도 보너스 |
| 업그레이드 비용 | 비용 = 기본 비용 + 현재 레벨 x 증가값 |

공식에는 반드시 예시 계산을 붙입니다. 예시 계산이 있어야 문서가 실제로 작동하는지 확인할 수 있습니다.

## 문서 실습: 시스템 공식 설계서

**미션:** 자신의 게임에서 숫자 계산이 필요한 시스템 하나를 골라 공식을 작성합니다.

```text
공식 이름:

1. 이 공식이 필요한 이유
-

2. 입력값
- 값 1:
- 값 2:
- 값 3:

3. 출력값
-

4. 공식
-

5. 예시 계산
- 입력:
- 계산:
- 결과:

6. 상한/하한
- 최소값:
- 최대값:

7. 밸런스 의도
-

8. 조심할 점
-
```

### 작성 예시

```text
공식 이름: 손님 만족도 계산

1. 이 공식이 필요한 이유
- 손님에게 맞는 아이템을 판매했을 때 만족도 변화를 일관되게 계산하기 위해 필요하다.

2. 입력값
- 값 1: 기본 만족도 변화
- 값 2: 직업 적합도
- 값 3: 던전 위험 대응 보너스

3. 출력값
- 최종 만족도 변화량

4. 공식
- 최종 만족도 = 기본 만족도 + 직업 적합도 + 위험 대응 보너스

5. 예시 계산
- 입력: 기본 만족도 5, 직업 적합도 10, 위험 대응 보너스 8
- 계산: 5 + 10 + 8
- 결과: 만족도 +23

6. 상한/하한
- 최소값: -20
- 최대값: +30

7. 밸런스 의도
- 한 번의 좋은 판매로 큰 보상을 주되, 만족도가 한 번에 너무 많이 오르지 않도록 제한한다.

8. 조심할 점
- 보너스가 중복되어 항상 최고 만족도가 나오지 않게 한다.
```

### 생각해보기

1. 공식에 상한과 하한이 없으면 어떤 문제가 생길까요?
2. 복잡한 공식이 항상 좋은 밸런스를 만들까요?
3. 예시 계산을 문서에 넣으면 개발자와 기획자에게 어떤 도움이 될까요?

## 오늘의 정리

- 시스템 공식은 같은 입력에서 같은 결과가 나오게 만드는 약속입니다.
- 좋은 공식 문서에는 입력값, 출력값, 공식, 예시 계산, 상한/하한, 밸런스 의도가 들어갑니다.
- 처음에는 단순한 공식으로 시작하고, 테스트 결과를 보며 조정하는 것이 좋습니다.
