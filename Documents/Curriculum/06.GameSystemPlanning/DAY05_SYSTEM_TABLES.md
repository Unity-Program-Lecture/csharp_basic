# DAY 05: 시스템 테이블과 데이터 설계

오늘은 게임에 필요한 데이터를 표로 정리합니다. 시스템 테이블은 개발자가 실제 데이터로 옮기기 전에, 기획자가 어떤 값이 필요한지 정리하는 설계도입니다.

## 1. 핵심 개념: "메뉴판과 재고표 만들기"

식당에는 메뉴판과 재고표가 있습니다. 메뉴 이름, 가격, 재료, 판매 여부가 정리되어 있어야 주문과 계산이 가능합니다.

게임도 마찬가지입니다. 아이템 이름, 가격, 등급, 효과, 획득 방법이 정리되어야 상점, 인벤토리, 보상 시스템이 제대로 작동합니다.

### 이 단어는 무슨 뜻인가요?

- **시스템 테이블**: 게임에서 사용할 데이터를 행과 열로 정리한 표입니다.
- **행**: 하나의 데이터 항목입니다. 예를 들어 아이템 하나입니다.
- **열**: 데이터 항목이 가진 속성입니다. 예를 들어 이름, 가격, 효과입니다.
- **ID**: 데이터를 구분하기 위한 고유한 이름이나 번호입니다.
- **확장성**: 나중에 데이터가 늘어나도 구조가 무너지지 않는 성질입니다.

## 2. 테이블은 읽는 사람을 위해 만든다

테이블은 기획자 혼자 보기 위한 메모가 아닙니다. 개발자, 아티스트, QA가 함께 봅니다.

| 좋은 테이블 | 문제가 되는 테이블 |
| :--- | :--- |
| ID가 고유하다 | 같은 이름이 여러 번 나온다 |
| 열 이름이 분명하다 | "기타", "비고"에 중요한 내용이 몰린다 |
| 값의 단위가 있다 | 10이 초인지 골드인지 알 수 없다 |
| 빈칸 규칙이 있다 | 빈칸이 의도인지 누락인지 모른다 |
| 나중에 추가하기 쉽다 | 새 데이터를 넣을 때 열 구조가 깨진다 |

### 작성 예시

테이블 이름: 상점 판매 아이템 테이블

테이블 목적: 손님에게 판매할 수 있는 아이템의 기본 정보를 관리한다.

| ID | 이름 | 등급 | 가격 | 효과 | 획득 방법 | 사용 조건 | 비고 |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| item_001 | 낡은 검 | 일반 | 100 | 공격 위험 대응 +5 | 기본 제작 | 전사 손님 | 초반 기본 무기 |
| item_002 | 튼튼한 방패 | 일반 | 120 | 방어 위험 대응 +7 | 기본 제작 | 기사 손님 | 방어형 던전에 유리 |
| item_003 | 해독 포션 | 희귀 | 180 | 독 위험 대응 +12 | 독초 재료 제작 | 모든 손님 | 독 던전에서 추천 |

컬럼 설명:
- ID: 개발에서 사용할 고유 식별자
- 이름: 플레이어에게 보이는 아이템 이름
- 등급: 일반, 희귀, 영웅 등
- 가격: 상점 판매 가격, 단위는 골드
- 효과: 손님 만족도나 공략 확률에 영향을 주는 설명
- 획득 방법: 제작, 보상, 구매 등
- 사용 조건: 특정 직업이나 상황 제한
- 비고: 기획 의도나 주의 사항

주의할 규칙:
- ID는 한 번 정하면 중복해서 쓰지 않는다.
- 가격 단위는 모두 골드로 통일한다.
- 효과 수치는 DAY 04의 만족도 공식과 연결한다.

## 오늘의 정리

- 시스템 테이블은 게임 데이터를 표로 정리한 설계 문서입니다.
- 좋은 테이블은 ID, 열 이름, 단위, 빈칸 규칙이 분명합니다.
- 테이블은 공식, UI, 밸런스, QA와 연결되므로 읽기 쉽게 작성해야 합니다.
