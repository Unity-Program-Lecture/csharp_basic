# 🚀 6일차: 안전한 데이터 통로와 약속! (프로퍼티와 인터페이스)

오늘의 목표는 **"변수를 안전하게 보호하는 전용 문법(프로퍼티)을 익히고, 어떤 기능이 반드시 있어야 하는지 '설계 규칙'을 정하는 방법(인터페이스)을 배운다"**입니다.

---

## 1. 프로퍼티(Property): "변수인 척하는 메소드"
클래스의 중요한 정보를 외부에서 마음대로 바꾸지 못하게 막으면서도, 사용할 때는 변수처럼 편하게 쓰게 해주는 **'안전한 통로'**입니다.

### 💡 이 단어는 무슨 뜻인가요?
- **`get` (겟)**: 값을 **읽어갈 때** 실행되는 코드입니다. (읽기 전용 가능)
- **`set` (셋)**: 값을 **저장할 때** 실행되는 코드입니다. (쓰기 전용 가능)
- **`value` (밸류)**: `set`에서 새로 들어온 값을 가리키는 특수 이름표입니다.
- **자동 구현 프로퍼티**: 복잡한 로직 없이 단순히 변수를 보호만 할 때 쓰는 짧은 문법입니다. (`{ get; set; }`)

### 💻 실습 예제: 나이를 속일 수 없는 캐릭터
**미션:** 나이(Age) 변수를 프로퍼티로 만들어, 0보다 작은 값이 들어오면 0으로 고정되도록 안전 장치를 만들어 보세요.

<details>
<summary>코드 보기</summary>

```csharp
using System;

namespace Day06
{
    class Player
    {
        private int age; // 실제 데이터는 private으로 숨깁니다.

        public int Age
        {
            get { return age; } // 값을 읽을 때 실행
            set 
            { 
                // 값을 저장할 때 검사! (0보다 작으면 0으로 고정)
                if (value < 0) age = 0;
                else age = value;
            }
        }

        // 간단하게 쓸 때는 자동 구현 프로퍼티!
        public string Name { get; set; } 
    }

    internal class Program
    {
        static void Main(string[] args)
        {
            Player p = new Player();
            p.Name = "전사"; // 변수처럼 편하게 씁니다.
            p.Age = -10;    // 내부에서 set이 작동하여 0이 됩니다.

            Console.WriteLine("{0}의 나이: {1}", p.Name, p.Age);
        }
    }
}
```

</details>

## 2. 인터페이스(Interface): "사용 설명서 혹은 계약서"
클래스가 "나는 누구인가(설계도)"를 정의한다면, 인터페이스는 **"나는 이런 일을 할 수 있다(기능 약속)"**를 정의합니다.

### 💡 이 단어는 무슨 뜻인가요?
- **`interface` (인터페이스)**: 실제 알맹이(코드)는 없고 이름만 있는 메소드나 프로퍼티들의 모임입니다.
- **`I` 접두사**: C#에서는 인터페이스 이름 앞에 대문자 **'I'**를 붙이는 것이 약속입니다. (예: `IDamageable`)
- **구현 (Implementation)**: 인터페이스에 적힌 약속을 클래스에서 실제로 지키는(코드를 쓰는) 것을 말합니다.

### 💻 실습 예제: 데미지를 입을 수 있는 모든 것들
**미션:** IDamageable 인터페이스를 정의하고, 플레이어와 나무 클래스에서 각각의 특색에 맞게 데미지 처리 기능을 구현해 보세요.

<details>
<summary>코드 보기</summary>

```csharp
using System;

namespace Day06
{
    // 1. "데미지를 입을 수 있다"는 약속을 만듭니다.
    interface IDamageable
    {
        void TakeDamage(int amount); // "이걸 가진 애들은 무조건 이 기능을 만들어야 해!"
        int Hp { get; set; }         // 프로퍼티도 약속할 수 있습니다!
    }

    // 2. 플레이어는 데미지를 입을 수 있습니다.
    class Player : IDamageable
    {
        public int Hp { get; set; } = 100;
        public void TakeDamage(int amount)
        {
            Hp -= amount;
            Console.WriteLine("플레이어가 {0}의 데미지를 입었습니다. (남은 HP: {1})", amount, Hp);
        }
    }

    // 3. 나무(오브젝트)도 데미지를 입을 수 있습니다.
    class Wood : IDamageable
    {
        public int Hp { get; set; } = 50; // 나무에게는 내구도가 곧 Hp입니다.
        public void TakeDamage(int amount)
        {
            Hp -= amount;
            Console.WriteLine("나무가 쪼개집니다! (남은 내구도: {0})", Hp);
        }
    }

    internal class Program
    {
        static void Main(string[] args)
        {
            // 인터페이스의 강력함: 타입이 달라도 같은 약속을 지켰다면 하나로 묶을 수 있습니다!
            IDamageable target1 = new Player();
            IDamageable target2 = new Wood();

            target1.TakeDamage(10);
            target2.TakeDamage(10);
        }
    }
}
```

</details>

## 3. 왜 인터페이스를 쓰나요?
1. **표준화**: 여러 사람이 작업할 때, 메소드 이름을 통일할 수 있습니다.
2. **유연함**: 나중에 새로운 클래스가 추가되어도, 같은 인터페이스만 쓰고 있다면 기존 코드를 고칠 필요가 없습니다.
3. **다중 구현**: 클래스 상속은 한 명의 부모만 가질 수 있지만, 인터페이스 약속은 **여러 개**를 동시에 지킬 수 있습니다.

### 💻 실습 예제: 하늘을 나는 강아지?
**미션:** 여러 인터페이스를 한 클래스에서 동시에 구현(다중 구현)하여 다양한 기능을 가진 복합 객체를 만들어 보세요.

<details>
<summary>코드 보기</summary>

```csharp
interface IFlyable { void Fly(); }
interface IWalkable { void Walk(); }

// 강아지는 걷기도 하고, (마법으로) 날 수도 있습니다!
class MagicDog : IWalkable, IFlyable
{
    public void Walk() { Console.WriteLine("강아지가 걷습니다."); }
    public void Fly() { Console.WriteLine("강아지가 하늘을 납니다!"); }
}
```

</details>

## 5. 6일차 심화 미션: "특수 능력과 상호작용 시스템"

**[미션 목표]**
인터페이스를 사용하여 서로 다른 클래스(몬스터, 보물상자 등)에 공통적인 행동 규격(데미지 입기, 사용하기 등)을 정의합니다. 이를 통해 상속 관계가 아닌 클래스 간에도 동일한 메서드 호출을 가능하게 하는 설계 기법을 학습합니다.

---

### 1) 요구 사항

#### 1. 인터페이스 정의 (`Interface`)
* **`IDamageable`**: `TakeDamage(int amount)` 메서드와 `Hp` 프로퍼티를 가집니다. 데미지를 입을 수 있는 모든 대상에게 적용합니다.
* **`IUsable`**: `Use()` 메서드를 가집니다. 아이템이나 장치처럼 사용 가능한 대상에게 적용합니다.

#### 2. 다양한 대상 구현
* **Monster**: `IDamageable`을 상속받아 데미지 로직을 구현합니다.
* **WoodBox (나무 상자)**: `Monster`는 아니지만 `IDamageable`을 상속받습니다. 공격받으면 "상자가 부서지며 아이템이 나옵니다!"라는 메시지를 출력합니다.
* **Potion (물약)**: `IUsable`을 상속받아 사용 시 플레이어의 체력을 회복하는 로직을 구현합니다.

#### 3. 범용 공격 시스템
* 플레이어의 `Attack` 메서드가 `Monster` 타입이 아닌 `IDamageable` 타입을 매개변수로 받도록 수정합니다. 
* 이제 플레이어는 몬스터와 나무 상자를 모두 공격할 수 있습니다. (다형성 활용)

---

### 2) 프로그래밍 힌트
* `interface` 내부에는 구현부(`{ }`) 없이 세미콜론(`;`)으로 끝나는 메서드 선언만 작성합니다.
* 클래스에서 인터페이스를 상속받을 때는 부모 클래스 이름 뒤에 쉼표(`,`)를 붙여 추가합니다. (예: `class Slime : Monster, IDamageable`)
* `IDamageable target`과 같이 인터페이스를 타입으로 사용하면 해당 인터페이스를 구현한 어떤 객체든 전달받을 수 있습니다.


**[심화 과제 (선택 사항)]**
- **다중 인터페이스 구현**: `ExplosiveBarrel (폭발통)` 클래스를 만들어 `IDamageable`을 구현하면서, 공격받아 파괴될 때 주변에 데미지를 입히는 로직을 추가해 보세요.
- **인터페이스 체크**: `if (target is IUsable)`와 같은 키워드를 사용하여 객체가 특정 기능을 가지고 있는지 확인하는 로직을 고민해 보세요.
