# C# 힙 객체의 내부 구조와 GetHashCode의 관계

이 문서는 `C#_코드의_실행원리와_메모리동작_방식.md`에서 다룬 '힙(Heap)' 메모리 영역에 생성되는 객체가 실제로 어떤 형태를 띠고 있는지, 그리고 `GetHashCode()`가 이 구조와 어떤 관계가 있는지 심층적으로 설명합니다.

---

## 1. 힙에 저장되는 객체의 실제 모습 (화물과 꼬리표)

우리가 클래스를 통해 `new` 키워드로 객체를 생성하면, 힙(창고)에는 우리가 정의한 필드 데이터만 달랑 저장되는 것이 아닙니다. CLR(공용 언어 런타임)은 객체를 관리하기 위해 두 가지 '숨겨진 꼬리표'를 앞에 붙입니다.

### 📦 객체의 3단 구조
1. **Object Header (Sync Block Index):** 4~8바이트 공간. 객체의 상태 정보가 담긴 '헤더'입니다.
2. **Method Table Pointer (Type Handle):** 4~8바이트 공간. 이 객체가 어떤 클래스인지(타입 정보)를 가리키는 주소입니다.
3. **Instance Data:** 우리가 클래스에 정의한 실제 데이터(`int age`, `string name` 등)입니다.

---

## 2. Object Header: 객체의 다용도 꼬리표

Object Header는 평소에는 비어있거나 간단한 상태 값을 가지고 있지만, 특정 상황에서 매우 중요한 역할을 합니다.

*   **스레드 동기화 (lock):** 특정 객체에 `lock`을 걸면, 이 헤더를 통해 'Sync Block'이라는 관리 공간과 연결되어 다른 스레드의 접근을 제어합니다.
*   **해시코드 저장 (GetHashCode):** 바로 이 문서의 핵심 주제입니다.

---

## 3. GetHashCode()와 Object Header의 관계

C#에서 모든 객체의 조상인 `object` 클래스는 `GetHashCode()` 메서드를 제공합니다. 이 메서드는 객체를 식별할 수 있는 고유한 숫자(해시코드)를 반환합니다.

### 🔍 해시코드는 어디서 올까?
1.  **최초 호출:** `GetHashCode()`를 처음 호출하면 CLR은 객체의 고유한 값을 생성합니다. (단순히 메모리 주소를 쓰는 것이 아니라 복잡한 알고리즘을 사용합니다.)
2.  **헤더에 기록:** 생성된 이 숫자는 **Object Header** 영역에 몰래 기록됩니다. 이를 **캐싱(Caching)**이라고 합니다.
3.  **이후 호출:** 다시 `GetHashCode()`를 부르면 새로 계산하지 않고, 헤더에 적어둔 숫자를 즉시 반환합니다.

---

## 4. 왜 메모리 주소를 그냥 쓰지 않을까? (GC의 비밀)

많은 사람들이 "해시코드는 객체의 메모리 주소 아니야?"라고 생각하지만, C#의 힙 메모리에서는 주소가 계속 변합니다.

*   **가비지 컬렉터(GC)의 이동:** GC는 메모리 창고를 정리할 때, 구멍 난 공간을 메우기 위해 살아있는 객체들을 옆으로 밀어서 옮깁니다. 즉, **객체의 물리적 주소가 수시로 바뀝니다.**
*   **고유성 유지:** 만약 해시코드가 주소값이라면, GC가 청소를 한 번 할 때마다 모든 객체의 해시코드가 바뀌는 대혼란이 일어날 것입니다.
*   **해결책:** 해시코드가 한 번 생성되어 **Object Header**에 박제되면, 객체가 힙 안에서 어디로 이사를 가든 해시코드는 변하지 않고 유지됩니다.

---

## 5. 요약: 힙 구조가 주는 이점

*   **Type Handle** 덕분에 객체는 자신이 누구인지(어떤 클래스인지) 런타임에 알 수 있습니다.
*   **Object Header** 덕분에 주소가 바뀌는 힙 환경에서도 객체는 자신만의 고유한 번호(`GetHashCode`)를 평생 간직할 수 있습니다.

> **비유:** 창고(Heap)에 들어온 화물(Object)이 창고 정리를 위해 위치(Address)가 바뀌더라도, 화물 상자 전면에 붙여둔 관리용 스티커(Object Header)에 적힌 관리 번호(HashCode)는 바뀌지 않는 것과 같습니다.
